## Planner decisions (Claude's discretion), recorded with their reasons

- **The accumulator lives in internal/krl, takes parsed certificates and imports nothing new.** The early plan checked only that krl importing tlog has no cycle, which holds (tlog imports wire, wire imports trust, cert and directory). It missed that at 1aa0b7d the two agent binaries link krl, wire, directory and webauthn but not tlog (`go list -deps` of the three binaries), so krl importing tlog would link tlog and its capabilities into both agents. `krl.DrainMax.Add(leaf, *ssh.Certificate)` needs only the ssh import krl.go and parse.go already have. A new leaf package was the alternative; it adds a package and a capslock row for no gain.
- **One list of the leaf kinds that carry certificates: `tlog.LeafCertificates`.** The signer's walk and audit's walk both call it, so they cannot disagree about which kinds count. It returns the certificate of an issue, login_issue, host_issue, machine_issue or probe_issue leaf (either probe polarity) and every certificate of the request a revocation_recovery leaf carries (`wire.ParseRecoverySigningBytes(body.Request).Certificates`, kept or revoked); the early plan said the recovery leaf carries certificates, but `tlog.RecoveryBody` (leaf.go:1314) holds the signed request and its entries. An exhaustive test makes a future leaf kind fail until it is classified (T-03-450).
- **The scan feeds at install, and a missing scan refuses.** `rebuildLogFromWith(ctx, db, v, opts)` feeds the accumulator and checks `--previous` only when asked; `InstallBundleWithPrevious`, through a log writer built by `newLogWriterWith`, and doctor's `LogDrain` ask; serve's start-up, `CheckLog`, ca-init and `ca-rotate prepare` (which keep `newLogWriter` and the plain rebuild) do not, so none of them pays for the scan or gains its parse refusal. The feed is the last step of each leaf's callback, after the leaf's kind decode and index applies: the accumulator sees only leaves the rebuild (and, in audit, the kind switch) has already accepted, so every existing refusal text keeps its precedence. The install binding refuses `drain_scan_missing` when it is handed no accumulator, so a future path cannot skip it by omission. `rebuildLogFrom` keeps its signature as a wrapper, so no existing test changes.
- **A switch is recognised by its newly draining entries.** An install is a switch when the bundle has a draining entry the installed bundle does not have as draining. The chain rule admits no other way to create one. `--previous` is verified whenever it is given and required for a switch.
- **The chain rule gets the two policies.** `checkCATransitions(prev, next, prevPol, nextPol)`; checkSuccessorChain has parsed both before the call (verify.go:360-367). The floor is `trust.DrainFloor`, one exported function that the chain rule, `BuildSuccessor` and the ceremony's CA-change line all call, so the three cannot drift (T-03-456). DrainMargin and MaxDrainAllowance are constants in internal/trust; a test in internal/krl asserts DrainMargin equals PruneMargin, because trust cannot import krl.
- **The serving configuration is the zero value.** `signer.Config.Recovery` is false by default and `recover-revocations` alone sets it, so a caller that forgets the field gets the strict behaviour. A recovery signer holds no CA key, every issuance path refuses `ca_not_configured` (issue.go:88, login.go:63, hostissue.go:96, machineissue.go:144, probeissue.go:110), and `Serve` refuses `recovery_configuration`.
- **`keystore.Holds` fails closed.** A backend that does not implement it, or that returns an error, counts as holding the key. Software: lstat of the generation's file, any entry counts. Agent: the agent lists the fingerprint, as a plain key or as the key behind a certificate identity (`(*ssh.Certificate).Key`), because the agent signs with the private key behind a certificate identity when asked for it. doctor reads software by a file check (it must not need the passphrase) and opens the agent backend only when the stored backend is the agent; TPM and PIV cannot hold a generation of a draining entry before 03-12f, because prepare refuses them.
- **retire-key proves what it acts on, then removes, then re-checks.** `signer.RetireKeys` reads the stored bundle through `checkStoredTrust`, walks the verified log and runs `checkBundleLogged` against its last bundle_install, as `InstallBundle` and `New` do, so it never acts on a bundle the log does not record; the pure `retireTargets` pairs each draining entry with its generation row and refuses `draining_generation_unknown` (no row) and `draining_names_the_active_generation`; then it opens the role's active generation and signs a test message first, and a failure refuses `active_key_unusable` and removes nothing. Removal goes through the optional interface `keystore.GenerationRemover`; the software backend derives the path from (role, generation), checks the directory is private, unlinks (never follows a link) and fsyncs. Before the unlink the software backend decrypts a regular file with the passphrase that retire-key already holds (it proved the active key with it), compares the key's fingerprint with the entry's, and removes nothing on a mismatch or when the file cannot be decrypted: the generation number alone is never trusted. The cost is one more scrypt per drained generation (a low-factor passphrase in tests); a symlink is unlinked without decrypting, since it is no key.
- **A restored pre-switch database is fenced by the runbook, not by the signer.** After a restore from before the switch the restored bundle has the old key as its active key and no draining entry, so nothing but the key's absence stops serve once `recover-revocations` has released the marker; an agent or pkcs11 reload can bring the old key back. The plan states RC-03 as conditional, lists the residual and has the runbook check the backend before the start. No durable hold is built here.
- **`stopped_at` in STATE.** One scoped edit replaces `stopped_at: "Completed 03-12d-PLAN.md (PR #109)"` with `stopped_at: "Completed 03-12e-PLAN.md (PR #N)"`, N being this plan's PR (the three tracking commands do not touch it).

## The output contract

These names and texts are fixed, byte for byte where tests match them.
- **internal/trust:** `const DrainMargin = 300` (seconds), `const MaxDrainAllowance = 7 * 24 * time.Hour`, `func DrainFloor(issuedAt string, ttlPrev, ttlNext uint64) (uint64, error)` (Unix seconds of issuedAt plus the larger TTL plus DrainMargin; an issuedAt before 1970, or any sum that would overflow, is an error), `func RoleMaxTTL(p *Policy, role string) (uint64, bool)`, `SuccessorOptions.CASwitch []string` and `SuccessorOptions.DrainAllowance time.Duration`. Chain refusals read `CA <role> generation <g>: <reason>` with the reasons of 03-12b unchanged and two new ones: `trusted_until <t> is before the switch floor <f> (issued_at plus the larger max_ttl_seconds of the two policies plus 300 s)` and `the switch floor cannot be computed: <error>` (an issued_at or a draining trusted_until before 1970 is such an error).
- **internal/krl:** `type DrainEntry struct{ValidBefore, Leaf, Serial uint64; KeyID string}`, `NewDrainMax() *DrainMax`, `(*DrainMax).Add(leaf uint64, c *ssh.Certificate) error` (a nil certificate or one without a signature key is an error, from the first version on; more than `MaxDrainKeys` = 4096 distinct keys is `ErrDrainTooManyKeys`), `(*DrainMax).For(caKey []byte) (DrainEntry, bool)` (nil-safe: on a nil receiver it returns the zero entry and false, so a missing accumulator is a refusal and never a panic), `DrainBindingHolds(maxValidBefore, trustedUntil uint64) bool` (`!EntryLive(maxValidBefore, trustedUntil)`: the one binding rule that the signer's `checkSwitchInstall` and audit's install both call), `EarliestTrustedUntil(validBefore uint64) (uint64, bool)` (validBefore plus PruneMargin; false when that saturates). On a tie the earliest leaf keeps the entry.
- **internal/tlog:** `LeafCertificates(l Leaf) ([]*ssh.Certificate, error)`: none for a leaf that carries none; an error for a certificate that does not parse, is not a certificate, or whose encoding is not canonical, naming the leaf kind and, for a recovery leaf, the certificate's position in its request.
- **internal/signer:** `ErrDrainWindowTooShort` (`drain_window_too_short`), `ErrDrainWindowTooLong` (`drain_window_too_long`), `ErrInstallPreviousRequired` (`install_previous_required`), `ErrInstallPreviousInvalid` (`install_previous_invalid`), `ErrInstallPreviousNotExtended` (`install_previous_not_extended`), `ErrDrainScanMissing` (`drain_scan_missing`), each wrapping `ErrBundleInstall`; `InstallBundleWithPrevious(ctx, db, be, pins, threshold, bundle, bundleSigs, policy, policySigs, clock, previous []byte) (*trust.Bundle, []DrainNote, error)` with `InstallBundle` as the wrapper that passes nil and drops the notes, `DrainNote{Role string; Generation uint32; TrustedUntil string; Max krl.DrainEntry; Recorded bool}` (one per newly draining entry), `checkSwitchInstall` (the binding, the upper bound and the previous requirement, called before `logTx`; it refuses `ErrDrainScanMissing` first when it is handed no accumulator), `drainFeed(acc *krl.DrainMax, idx uint64, l tlog.Leaf) error` (the signer's one call into `tlog.LeafCertificates`; its error wraps `errLogMismatch` with the text `drain scan: leaf <idx> (<kind>): <error>`) and `newLogWriterWith(ctx, db, logKey, clock, opts rebuildOptions)` (`newLogWriter` is it with no options; only `InstallBundleWithPrevious` sets the drain option); `LogDrain(ctx, db, logKey) (*krl.DrainMax, error)`; `Config.Recovery bool`; `ErrDrainingKeyUsable` (`draining_key_still_usable`); `ErrRecoveryConfiguration` (`recovery_configuration`, declared in drain.go beside `ErrDrainingKeyUsable`); `RetireKeys(ctx, db, be, role) (*RetireResult, error)` and the pure `retireTargets(b *trust.Bundle, gens []signerdb.CAGeneration, role string) ([]retireTarget, error)`; `RecoveryResult.BeyondDrain []BeyondDrain`.
- **Install refusal texts.** `drain_window_too_short: the switch of CA <role> ends trust at <t>, but the log records a certificate of generation <g> valid until <v> (serial <s>, key ID <k>, leaf <l>); the earliest acceptable trusted_until is <e>`, with `<e>` = `none (that certificate never expires)` when ValidBefore plus 300 saturates. `drain_window_too_long: the switch of CA <role> ends trust at <t>, above the latest acceptable <b>`. `install_previous_required: a switch install needs --previous, an export-log file of this log kept off the box`. `install_previous_invalid: <reason>`. `install_previous_not_extended: the log does not extend the checkpoint in --previous (it covers <n> entries, this log has <m>)`. `drain_scan_missing: the install was handed no scan of the log`.
- **install-bundle output,** after its CA lines, one line per newly draining entry: `drain <role> generation <g> until <t>; the last certificate the log records for it is valid until <v>` (`none recorded` when there is none).
- **keystore:** `GenerationHolder` (`Holds(role Role, generation uint32, fingerprint, location string) (bool, error)`), `Holds(b Backend, role, generation, fingerprint, location)` (a backend without the interface returns `true` and `ErrHoldsUnsupported`), `GenerationRemover` (`RemoveGeneration(role Role, generation uint32, fingerprint, location string) error`; the software backend decrypts a regular file and compares its key's fingerprint before the unlink, with `ErrGenerationFileMismatch` and `ErrGenerationFileUndecryptable` for the two refusals); software exports `GenerationHeld(stateDir string, role keystore.Role, generation uint32) (bool, error)` for doctor.
- **retire-key** (`keyroster-signer ca-rotate retire-key --state-dir D --role R [--backend-opt K=V]`): per draining generation one line `role <r> generation <g> <fingerprint>: removed`, `... : not held` or, for the software backend, `... : not removed: the file holds another key (<fingerprint of that key>)` or `... : not removed: the file cannot be decrypted: <error>` (both count as still held and remove nothing), or, for the agent backend, `... : still held by the agent; write this public key line into <file> and run: SSH_AUTH_SOCK=<socket> ssh-add -d <file>`, followed by the draining entry's public key line and, for each certificate identity of that key that the agent holds, a second line `... write this certificate line into <file>-cert.pub and run: SSH_AUTH_SOCK=<socket> ssh-add -d <file>-cert.pub` with that certificate's public line, and then `run retire-key again`, where `<socket>` is the stored backend's `socket` option and not the operator's default agent; then `retire-key: no draining key of role <r> is held` and exit 0, else exit 1 with `retire_key_incomplete: <n> draining generation(s) of role <r> are still held`. Refusals: `no_draining_entry`, `active_key_unusable`, `draining_generation_unknown`, `draining_names_the_active_generation`, `rotation_role_not_supported`, `rotation_not_supported_on_backend`, `restore_recovery_pending`, and the log refusals of `checkBundleLogged`. It writes no log leaf.
- **serve refusal:** `draining_key_still_usable: the backend still holds generation <g> of the <role> CA (<fingerprint>), which the installed bundle drains; run keyroster-signer ca-rotate retire-key`, with `cannot tell whether the backend holds it: <error>` in place of the second clause when Holds fails or is unsupported.
- **doctor:** FAIL `draining_key_still_usable: <role> generation <g> <fingerprint> is still held by the backend` and, per CA role with an active key, OK `switch_floor: <role> generation <g>: the certificate that sets the earliest trusted_until a switch could carry is serial <s> (key ID <k>, valid until <v>); the earliest is <e>` or `switch_floor: <role> generation <g>: the log records no certificate of this key; the earliest is the floor`.
- **Recovery output,** after the existing line, one line per carried certificate of a draining key whose ValidBefore is above its trusted_until minus 300 s: `warning: carried certificate serial <s> (key ID <k>, <kept|revoked>) of the draining <role> CA generation <g> is valid until <v>, after <t> minus 300 s; a kept one stops working at <t>`.
