<objective>
Remove the TOFU prompt: enrolled hosts obtain and renew host certificates by proof of possession of their host keys, under names only an admin signed, and users' SSH clients trust exactly those names through a CLI-managed @cert-authority line and a verified revoked-hosts list. Revoking a host ends its certificates, its keys and its enrollment.

Purpose: AGENT-06, REVOKE-04, and REVOKE-01's host subject (D-09, D-16, D-19). Roadmap success criterion 4, first half.

Output: the owner's T-03-100 decision (Task 1), the host issuance path (wire, signer, leaf kind 11, audit rule), agent renewal and install with served-certificate self-test, known-hosts management in the CLI (admin sync, and refresh at login under the recommended answer), `keyroster revoke host`, an e2e test with no TOFU prompt, vectors, runbooks, and a PR.

**A design decision (Claude's discretion) and an owner decision, recorded here.**
- No separate challenge round trip: replay is stopped the way every other signer request stops it (request ID unique across all paths, created_at within ±300 s), and the host key's signature over the exact request is the proof of possession. The closed agent operation set grows by one route, POST /api/v1/agent/hostcert.
- **Owner decision before implementation (Task 1): who receives the signed directory for host trust (T-03-100).** The directory stays admin-only on the main listener. A non-admin user's CLI can verify host names only from the whole admin-signed directory, so giving every signed-in user exact host names widens who sees the directory beyond what D-03 locked. The first draft decided that itself and asked the owner only at the merge gate; the owner now decides it in Task 1, before any code. Tasks 2 and 3 do not depend on the answer (the tracer proves the client side with the admin route `keyroster known-hosts sync`); Task 4 implements the recommended answer `redeem-directory`: the server includes the directory in the successful `keyroster login` redeem answer and the CLI verifies it itself. Serving the signed directory to unauthenticated clients would widen what Phase 2 exposed even further and is not an option.
</objective>
