## Part B (03-09b): binding scope

03-09b is written after this plan lands (Q-09-1). It must cover each item below. The old 03-09's Task 4 and its known-hosts cases are its starting point.

**D2, client host trust.**
- `keyroster known-hosts sync` (admins) and the refresh at `keyroster login` write three files.
  - **~/.ssh/keyroster_known_hosts.** One `@cert-authority <names> <key>` line per trusted host CA of the root-verified bundle, over the principals of the active entries of a directory the CLI verified itself (admin quorum under the root-signed policy, the bundle's installation ID). There is never a wildcard, `?`, `*` or `,` in a name.
  - **~/.ssh/keyroster_revoked_hosts.krl**, from a KRL verified with krl.VerifyManifest.
  - **~/.ssh/keyroster_ssh_config.** One Host block over every name the verified directory has ever held (active, disabled and removed), from a bounded CLI state file in the CLI's config directory. It always sets:
    - `UserKnownHostsFile ~/.ssh/keyroster_known_hosts` and `GlobalKnownHostsFile ~/.ssh/keyroster_known_hosts`;
    - `StrictHostKeyChecking yes`, `UpdateHostKeys no` and `VerifyHostKeyDNS no`;
    - `RevokedHostKeys ~/.ssh/keyroster_revoked_hosts.krl`.

    There is no fallback to ~/.ssh/known_hosts.
- **The documented costs:**
  - a managed name is unreachable until its host has a certificate;
  - a disabled or removed name is refused;
  - names removed before the CLI's first verified sync are not covered.

## Edge Coverage (spec-less fallback, this plan)

**Flagged assumptions (UNVERIFIED in this repository).**
- sshd serves, per algorithm, the first host key with a certificate. The fake models it, and the e2e proves one key per algorithm for two algorithms on real sshd.
- HostCertificate is fatal inside a Match block (upstream servconf.c). The agent avoids it either way (hostcert_in_match).
- HostKeyAlias makes the client look up and check principals against the alias without the port. The e2e proves it on the CI OpenSSH builds.
- The plain-key fallback is proven in CI by `existing_known_hosts_still_accepted` with a forced certificate algorithm.
- An RSA-only host cannot enroll today (hostSigners, enroll.go:212-213).

**The remaining window without a certificate** (T-03-343, accepted, corrected).
- Re-delivery closes the lost-answer cases: a 503 after the signer committed, a late post, an abandoned request, and a lost first answer. The retry, or any later request inside the window, gets the existing certificate.
- What remains:
  - a server or fetcher that withholds every answer;
  - a cert_revoked hold until a new directory version;
  - after an entry rename, an installed certificate lost inside the window: the re-delivered certificate carries the old kr3 sub, which VerifyAnswer refuses, so the host waits out the window.
- A latest certificate can no longer expire inside its window: the signer chooses the lifetime, which equals CapSeconds (Q-09-6), and the window is at most a third of it. So a lagging agent cap, raised or lowered, strands no host.

**Edges:**
- **Ordering:**
  - the install order and the crash table, rollbacks included;
  - the request order (attempts, then outbox) and the answer order (certificate file, attempts, outbox);
  - GC only after commit;
  - abandonment at 330 s, an orphan request included.
- **Concurrency:** Apply and HostCerts under apply.lock; HostIssue under s.mu with every bound read from the in-memory index, which loadLog refreshes after a failed transaction.
- **Trust:**
  - principals only from the entry;
  - the installation binding, every signed field bound;
  - pop.hosts, revoked keys and the cert_revoked hold;
  - the window from the cap in force, keyed by host key;
  - foreign HostCertificate lines;
  - a candidate never committed after a crash.
- **Failures:**
  - a missing, invalid or unreadable record (loud, never an error);
  - served_cert_mismatch, a reload lag, the algorithm disabled;

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| host root (agent) → keyroster-server → signer | A host may obtain certificates only for its own admin-signed name and listed keys, and only at a bounded rate per host key |
| signer → agent | Every answer (issued, re-delivered, kept or adopted) is verified against the state in force before it is installed |
| fetcher (unprivileged) → applier (root) | Spool answers are untrusted input, bound to the applier's own request IDs and fully verified |
| agent → sshd configuration | The one drop-in, the certificate files and the record must agree after any crash; foreign configuration is never edited |
| log → audit verify | Every host certificate and every bound must be re-provable from the log alone |
| heartbeat → admins | Host-reported certificate facts are bounded and escaped, and never the source of revocation |
