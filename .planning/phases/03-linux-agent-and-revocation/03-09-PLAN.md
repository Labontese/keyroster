<objective>
Remove the TOFU prompt: enrolled hosts obtain and renew host certificates by proof of possession of their host keys, under names only an admin signed, and users' SSH clients trust exactly those names through a CLI-managed @cert-authority line and a verified revoked-hosts list. Revoking a host ends its certificates, its keys and its enrollment.

Purpose: AGENT-06, REVOKE-04, and REVOKE-01's host subject (D-09, D-16, D-19). Roadmap success criterion 4, first half.

Output: the host issuance path (wire, signer, leaf kind 11, audit rule), agent renewal and install with served-certificate self-test, known-hosts management in the CLI (refreshed at login), `keyroster revoke host`, an e2e test with no TOFU prompt, vectors, runbooks, and a PR.

**Design decisions (Claude's discretion), recorded here.**
- No separate challenge round trip: replay is stopped the way every other signer request stops it (request ID unique across all paths, created_at within ±300 s), and the host key's signature over the exact request is the proof of possession. The closed agent operation set grows by one route, POST /api/v1/agent/hostcert.
- The directory stays admin-only on the main listener. Non-admin users get the host names from a directory the server includes in the successful `keyroster login` redeem answer, which the CLI verifies itself; serving the signed directory to unauthenticated clients would widen what Phase 2 exposed.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| agent (host root) → signer | A host may request certificates only for its own admin-signed names and keys |
| server → user CLI | The server delivers the directory and KRL; the CLI verifies both |
| user's ssh client → hosts | Trust is limited to exact names per CA line |
