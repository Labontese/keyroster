## Planner decisions (Claude's discretion), recorded with their reasons

- **D1. Four tasks.** The tracer (the account check and its reports), the matrix, the real unit with the runbook, and the gates. The two todos that this plan first held (a rollback that keeps a landed removal; a recovery that revokes every lost probe certificate) touch other trust boundaries and moved to plan 03-10d by owner decision Q-S; this plan shares no task with them. Its edits of apply.go, probegate.go and probegate_test.go (the served-certificate site, the gate, the hold reasons) are the lines that 03-10d must reconcile after this plan merges.
- **D2. One check, two entry points.** `checkProbeAccountFull(ctx, account, dump, compareTrust)` returns a result `{Reason, Line, Shadow, Notes}`; `accountKeyInput(root, account)` returns the string that enters the failure key (the passwd line, a separator and the effective password class: `absent`, `unreadable`, `empty`, `star`, `locked`, `hash` or `unparsable`) and needs no sshd. The gate, runProbes and forward's served-certificate site must all use the same key input, or `failure_backoff` would never match its own record.
- **D3. Only a definite exclusion holds.** `ExcludedDefinite(d, account, root)` returns why and whether the exclusion is certain; Excluded keeps its text and callers. A `user@host` entry that the agent cannot evaluate holds nothing: the positive probe decides, and a refusal is rolled back under `failure_backoff` (T-03-66 residual, unchanged). Reason: holding on 'may' would block every addition for ever on a host with `AllowUsers keyroster-probe@127.*`.
- **D4. The `!` case maps to `sshd_override`.** Under `usepam no`, a `!`-prefixed shadow field makes sshd refuse the account's logins (the distro harness's own comment, distro_test.go:98-99, records this for Alpine); whether it also refuses the unsigned PK_OK query is measured by TestDistroProbeAccountBang, and the rule's premise is asserted there (the cell `!` with UsePAM no must be refused, or the test fails and the rule is revisited). `usepam` absent from a dump means no PAM (the `!` case then holds), because reading it as yes would let a no-PAM host go live, be refused and loop through rollback. UNVERIFIED for the query until the matrix runs.
- **D5. `positive_refused_rolls_back` uses a cause the check cannot see.** PubkeyAcceptedAlgorithms with the Ed25519 certificate algorithm removed (`-ssh-ed25519-cert-v01@openssh.com`) makes sshd refuse the certificate before PK_OK; CASignatureAlgorithms limited to ecdsa is the fallback. sshd_config(5) documents both keywords (UNVERIFIED here which of them sshd checks before it answers the unsigned query; the first CI run decides, and the e2e records which one it used). DenyUsers moves to the new hold chain, where it is `account_excluded`.
- **D6. The flake is fixed by ordering.** `kr role add qa` is applied and reported (host directory version equals the current one, and status.json's last_apply carries it) before the spacing wait. An opportunistic pair runs inside that apply, under the lock, so after the report no other apply can start one before the mixed map. A retry-once with a fresh mixed change would cost about 105 s of the 110 s headroom of the probe lanes; the ordering costs none. The fix cannot be proven by one green run: Task 1 runs the test three times locally on 10.5p1 and twice more in CI, and says so.
- **D7. Hold chain in the e2e.** The e2e sets every cause at once (shell not nologin, a shadow hash, a Match block with `PubkeyAuthentication no`, DenyUsers) and removes them in the gate's order, each removal followed by a directory change that grants nothing so the next apply runs at once. It adds about 4 x 10 s to a lane that has about 110 s of headroom; holds spend no pair.
- **D10. Matrix account command is a script.** test/distro/probe-account.sh holds one arm per family (debian, rhel, alpine, arch) with exactly the command lines of the runbook; the matrix and the systemd smoke run the script; the runbook gate compares each runbook block with its arm. One source of truth.
- **D11. The account check never waits and never writes.** It runs only in the gate (widening, not exempt) and in the opportunistic pair, plus preflight and drift. `sshd -T -C` costs one exec per evaluation; a held addition evaluates it on every 60 s retry. Tests that count `fakeRunner.dumps` are listed under 'Existing tests this plan changes'.

**Password classes** (the only form in which a password field is kept; Fix rounds 1 and 2). Two sources are always combined and the worst class wins (hash, then empty, then locked, then star; `absent` and `unreadable` rank below star). Source 1 is passwd field 2 of the account's line when it is not `x`. Source 2 is <root>/etc/shadow, read whenever it opens, also when field 2 is not `x`: every line for the account is classified. Classes: `absent` (no usable password: shadow missing or without a line for the account, with field 2 `x`), `unreadable` (shadow did not open for a permission reason; a note, never a hold by itself), `empty`, `star` (exactly `*`), `locked` (starts with `!`, any rest), `hash` (anything else), `unparsable`. The open errors map in a closed way: ENOENT and ENOTDIR are `absent`; EACCES, EPERM and ELOOP (a symlink included) are `unreadable`; any other open error is `unparsable`. A shadow file that opens but is over 1 MiB, is not a regular file (a FIFO included; it is opened with O_NONBLOCK so that it cannot block the gate) or has a malformed account line (fewer than two fields) is `unparsable` too, and `unparsable` holds as `account_unparsable`, as the passwd check does for the same shapes (account.go:30-32, :54-92). `empty` holds as password_empty and `hash` as password_set; a passwd `*` with a shadow hash therefore holds. Which of the two sources sshd and PAM actually read in each case is recalled, not verified (UNVERIFIED), which is why neither is trusted over the other. The result also carries a flag `ShadowUnreadable` (the `unreadable` outcome of source 2), which is what the `permitemptypasswords` rule and the note `probe_shadow_unreadable` read.
