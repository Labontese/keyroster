<objective>
Phase tracer. Prove the most lockout-prone Phase 3 path end to end before any agent exists: an admin revokes a certificate from the CLI, the network-less signer records it and publishes a KRL that our own encoder wrote, signed through an installation-bound manifest, keyroster-server serves it, and real sshd refuses the certificate after a file swap with no reload.

The path, in order:
1. the D-04 checkpoint fixes the installation ID's form (Task 1);
2. the trust bundle gains the installation ID (the field the manifest repeats);
3. `keyroster revoke serial` → server admin route → signer → revocation table, revoke leaf, KRL, ops-signed manifest, krl_publish leaf;
4. GET /api/v1/krl → manifest verified against the root-pinned bundle → `ssh-keygen -Q` before the swap → symlink swap → sshd refuses, control accepted, same PID.

Purpose: REVOKE-01 (serial target), REVOKE-02 (own encoder, oracle), REVOKE-03 (detached signature, atomic install). It also settles the STATE blocker "unknown whether sshd re-reads RevokedKeys without a reload" with a test on both CI OpenSSH versions.

Output: internal/krl (serial sections and the manifest), the revoke wire format, signer revocation path, two new leaf kinds, server routes, the CLI command, the e2e tracer, golden vectors, the revoke runbook, and a PR through the merge gate. The strict parser, the other revocation targets, re-publish, pruning and the audit verify rules for the new kinds follow in 03-03.

Interim behaviour of `keyroster audit verify`, from this plan's merge until 03-03 merges: the exhaustive kind switch added in 02-01 refuses kinds 9 (revoke) and 10 (krl_publish) through its default branch with `not verifiable by this version`. No change to internal/audit/verify.go is needed for that; this plan only adds tests that pin it.
</objective>

## Budget Exception

This plan lists 43 files and projects 170k tokens, above the 15-file and 100k smart-zone thresholds. It is the phase tracer, so it must cross every layer the revocation path touches at least once: trust bundle, CLI, server, wire, signer state, log, KRL codec, sshd. The 02-01 precedent applies.
- **Split points examined.** Moving the installation ID out would let a manifest format ship without the field D-04 requires, and 03-04 would then change a pinned format. Moving the server route out would leave a tracer whose CLI cannot reach a remote signer, which is how the homelab runs.
- **What was moved out.** The strict parser, key-ID, key and SHA-256 sections, revocation by key ID, key and subject, re-publish, pruning, the full oracle in both directions, fuzz targets and the audit verify rules all moved to 03-03. The agent's apply engine is 03-05.
- **Breakdown.** 13 new production files, 13 edits, 10 tests (one is the fakeSigner edit in internal/server/server_test.go), 5 golden vectors, 2 gate baselines, 1 runbook.
- **Size route (revision 2026-10-23, checker scope warning): trim, not split.** The tracer (Task 2) now lists 25 files: the depguard entry and the revoke runbook, which its e2e never executes, moved to Task 3. The plan total is unchanged at 43 files and about 170k tokens, which is above the smart zone; at 25 files the tracer is still the largest task of this plan, and the split points above explain why it cannot shrink further without leaving a layer of the revocation path unproven.
