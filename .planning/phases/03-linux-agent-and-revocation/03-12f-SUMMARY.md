# Phase 03 Plan 12f: CA rotation, TPM and PIV generations Summary

The TPM and PIV backends now hold CA key generations: TPM generation N of at least 2 is `tpm/<role>-g<N>.tpmkey` and `.auth` with noDA, opened only by generation, held while either file has a directory entry and removed (both files, then one directory sync) only after the key file's fingerprint matched; PIV generations take the first slot of 0x87 to 0x95 that no generation row records, are opened and checked by the key in the recorded slot, and are removed by overwriting that slot with a throwaway key, with the management key read only for a card write. The backend gate accepts tpm and piv, doctor checks a draining TPM generation by its files, the command-level legs run on swtpm and on a pivfake-only fake card in new steps of e2e-tpm and build-piv, TestTPMCARotation runs end to end on swtpm, and the runbooks carry the per-backend text.
