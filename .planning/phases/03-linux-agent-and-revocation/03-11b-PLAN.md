<objective>
An automation host renews its machine certificate through keyroster-server by proof of possession of its own key, an admin ends a machine's access from the CLI, and both are proved against real binaries and a real sshd. This is the second half of machine identities (OQ-1 of 03-11); the signer half is on main (03-11, PR #95).
- The route `POST /api/v1/machine/renew` relays one `wire.MachineIssueRequest` to the signer through a budget of its own and answers the signer's certificate. It is the first anonymous route that reaches a signing path, so it is born complete: its own limiter, a body cap, strict JSON, the pop.machines pre-check, an allowlist of refusals that pass through, and one generic answer for everything else (T-03-397).
- `keyroster machine renew` signs on the automation host, never sends or writes the private key, checks the answer against the root-verified bundle and writes the certificate atomically. Unattended use is designed in: a bounded key file, `--passphrase-fd`, a deterministic `--if-due`, and a named error for an sk key file.
- `keyroster revoke machine` retires a machine: every live certificate of the name, the directory entry disabled, the entry's key with `--keys`, and the certificates issued in between. Its text names both holds that stop re-issuance until a newer directory version, and the runbook says how to re-run it after a signer restore.
- The e2e test and the three runbooks make the claim checkable: what CI runs, what is UNVERIFIED until the homelab drill (03-16).

Purpose: AUTH-06 (D-15) and REVOKE-01 (D-09, D-12) complete.

## Owner decisions (recorded, do not ask again)

All by Daniel. This plan implements these.
- **OQ-b1 = B, inside the agent share (2026-11-10).** A machine renew call takes a machine token (at most 2), then an agent token (the agent share stays 6), then a total token (12). Machines plus agents together stay at most 6, so logins, revocations, directory installs, forgets and the server's own reads keep at least 6 (Q-G1 unchanged); machines never hold more than 2 (D6 unchanged). Accepted cost: an agent catch-up burst that holds all 6 agent tokens delays a machine renewal up to `signerCallTimeout` (10 s), then 503 and a retry; under an anonymous flood that holds both machine tokens, agents have 4 for catch-up. The agent-share comment in internal/server/signer.go is reworded to say that anonymous machine calls take that share too (the growth rule is widened on purpose).
- **OQ-b2: one plan (Daniel, 2026-11-10).** This plan's own estimate (225k executor tokens at calibration factor 1; see Budget and verify) is above the 220k line, so the owner was asked after plan check 1 and chose one plan over the split; the cut line stays recorded in Not done here, last row.
- **03-11's decisions stay binding** and are not restated in full: OQ-1 (two plans; AUTH-06 and REVOKE-01 complete here), OQ-2 (sk machine keys stay; `--agent-key` only, with a touch; a named error for an sk file; sk-dummy in the e2e test; a real token UNVERIFIED), OQ-3 (no source_address now, T-03-405), OQ-4 (no automatic revoke on `machine remove`, a key change or a role loss; the hint and the rotate recipe's revoke step), 03-11's defaults 1 to 12 (default 1: one generic answer before identity; default 2 and its amendment: the key hold and the name hold, released by any newer directory version), and the restore order of its pre-merge review (`revoke machine` and `revoke host` are re-run for every pending disable AFTER signer-install step 3 has reinstalled the last lost version).
- **Veto-able defaults of this plan, adopted (b-C1 to b-C12):**
  - b-C1: the route is on the main port, not the agent port (automation hosts are not enrolled agents; the firewall rule of a restore also keeps machines away, which is intended).
  - b-C2: limits 30 per minute and burst 10 per client address, 300 and 100 in total, body at most 16 KiB (below the wire maximum on purpose; a real request is under 2 KiB).
  - b-C3: the CLI accepts only an active or next machine CA key of the root-verified bundle (03-12 decides whether a draining key is accepted).
  - b-C4: the answer's `req=` must be this request's ID (a server cannot hand back an older certificate of the same key).
  - b-C5: `--if-due` is deterministic: renew from issuance + 2/3 of the lifetime - j, j derived from the certificate's own hash, at most min(1 h, lifetime/10).
  - b-C6: `--out` naming the key file is refused, by path and by same file.
  - b-C7: `revoke machine` refuses a `probe.` name before sending.
  - b-C8: `machine renew` exits 0 for issued or not due, 1 for any refusal or failure, 2 for usage; automation reads the text.
  - b-C9: `revoke machine` prints a line on every run about certificates the key obtained under a former machine name (T-03-72).
  - b-C10: the machine e2e test runs in the existing `e2e-probe` job under a new tag, with no job name changed; the main lanes keep their headroom.
  - b-C11: accepted residual T-03-407 (the generic answer hides the text, not the timing).
  - b-C12: `keyroster audit verify` prints `machine certificates: N` when the log holds any.
- **Earlier decisions this builds on.** D6 (03-09: 12 per hour, a share of 2 of 12, own bucket), Q-G1 (03-08g: 16, 12, 6 and 2; interactive calls always have at least 6), D-R2 (03-09b: a repeated revoke does not renew a host key hold), D-03 (the directory reaches only admins and enrolled hosts, so identity is decided by the signer before any state fact), D-04 (the installation ID is in every signed request), D-10 (a revocation applies at the host's next poll), D-12 (REVOKE-01 is CLI-only in Phase 3), D-20 (runbooks are labelled run or UNVERIFIED), D-06 (probe certificates share the machine CA, so a `probe.` subject is never revoked by name).

## Planner decisions (Claude's discretion), recorded with their reasons

- **PD1. Five tasks, tracer first.** Task 1 is a tracer: one machine renews through the route and logs in at a real sshd, wired through every layer this plan touches (the route and its budget, the client, the first slice of the CLI, the e2e harness and the workflow that runs it). Tasks 2 to 4 expand it. Task 5 is docs, tracking, gates, the PR and the SUMMARY; the owner's merge follows it (`autonomous: false`). Task 1 is large on purpose: an anonymous route cannot be built in pieces, so it is born with every control of Task 1's list and its tests.
- **PD2. An allowlist, not a denylist of three details.** Design default 1 names the three identity details (`unknown_machine`, `machine_key_mismatch`, `machine_pop_invalid`). The route instead passes through only the 16 details of the table in Task 1 and collapses every other refused detail, so a detail added to the signer later is hidden by default (fail closed). The same fail-closed rule covers `CodeMalformed`: `unknown_message_type` stays 403 `signer_too_old`, `malformed_request` and `malformed_frame` keep their own detail with 400, and every other malformed detail becomes a constant 400 `malformed_request` with the specific detail only in the log (M110). This is default 1 and stricter; the order of the post-proof details stays the signer's guarantee (03-11's order mutants).
- **PD3. The share selector.** `acquire(ctx, share)` and `budgeted(ctx, b, share, call)` take one of `shareNone`, `shareAgent` and `shareMachine` instead of a bool. A machine call takes machine, agent, total, and gives them back in the reverse order; each wait gives back what it took when its ctx ends (the rule of the existing code).
- **PD4. A sibling for the failure mapping.** `machineSignerFailed(w, v, name, client, err)` applies the collapse before the code switch of `agentSignerFailed`, which writes an agent's status and logs agent fields and cannot be called. The switch's other arms (`unknown_message_type` gives 403 `signer_too_old`, other malformed gives 400, anything else gives 503) are the same. `decodeAgentJSON` is reused as is.
- **PD5. The client's names live in serverclient/machine.go**, not in wire: `MachineRenewPath`, `MaxMachineRenewBody`, `MachineRenewRequest`, `MachineRenewAnswer`, `MachineErrNotAuthenticated`, `Client.MachineRenew`.
- **PD6. A key file's type is read from its header, never from error text.** x/crypto (v0.58.0 in go.mod) returns a `*ssh.PassphraseMissingError` carrying the public key for an encrypted openssh-key-v1 file, and the bare text `ssh: unhandled key type` for an unencrypted sk file. The CLI reads the clear public key of the header with `ssh.Unmarshal` into a local struct and `ssh.ParsePublicKey`, and refuses sk and RSA by type before any prompt (Task 2 Step 0 re-reads the pinned source).
- **PD7. `--if-due` keeps no state.** j is the first 8 bytes of the SHA-256 of the certificate's wire bytes, big-endian, modulo m = min(3600, L/10) (0 when m = 0), so every run computes the same time and different machines spread out. The CLI computes it itself (constants named and cited) and does not import the agent's hostcert package.
- **PD8. `revoke machine` is `runRevokeHost` driven by a descriptor.** One function, `runRevokeEntry(kind)`, takes the kind's subject kind, CA role, lookup, keys, status accessors, label and the texts that differ. The host output stays byte-identical, and `TestRevokeHost` (unchanged) is the regression proof. The shared helpers (`sweepSubject`, the key revocation body with a label parameter, `checkHostTrustFloor`, `editDirectoryOutcome`, `recoveryKeptNotice`) are reused.
- **PD9. The e2e test runs serial.** It is not `t.Parallel`, never sets `genesisMachineMaxTTL` (03-10b's rule: only TestProbeSelfTestEndToEnd sets it) and uses no helper defined under the tag `e2eprobe`, so `-tags "e2e e2emachine"` compiles on its own.
- **PD10. Test cost.** The three packages with a 90 s delta stop are internal/server, internal/serverclient and cmd/keyroster. Every subtest builds its own state from a shared constructor and passes when run alone (`-run '^TestA$/^case$'`), because a mutant is run on one subtest; no subtest relies on a predecessor (the e2e test is the one exception, its steps are ordered by design).
- **PD11. No bare three-digit number in an output assertion.** `TestRevokeHost/success_line_says_agent_keeps_state` failed on cli-windows because its output held a random SHA-256 containing `403` (03-11's CI note; PR #96 fixes that test). Every new assertion on CLI output matches a full phrase, never a bare status number.
- **PD12. The stub server answers the renew path anonymously.** `dirEnv.handle` (cmd/keyroster/dirpipe_test.go) verifies an admin signature on every path except the trust document and the KRL; the renew route has none, so it gets its own branch before that check, served by `e.override["POST "+path]` and recording the body.
- **PD13. The plan copy goes first in Task 5**, before any gate that reads `files_modified` from the repository copy; it is checked LF and byte-identical with `cmp`.
- **PD14. The ROADMAP edit is checked by hand and by a gate.** GSD's tracking update ticked a neighbouring row by prefix match in 03-11. The executor reads every changed ROADMAP line, and the gate accepts exactly the 03-11b tick and the two count tokens.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| anonymous caller -> the renew route | The first anonymous route that reaches a signing path: limiter, body cap, strict JSON, the cached status, then one signer call; the answer reveals no per-entry fact before the signer verified the proof of possession |
| keyroster-server -> the signer | The server relays one request through a budget; the signer alone decides from the admin-signed directory and the proof of possession, never from the server's word |
| the CLI <- keyroster-server | The answer is untrusted: it is checked against the root-verified bundle and policy before a byte is written |
| the CLI <-> the key file or ssh-agent | The private key stays on the automation host; the key file is bounded, typed and cleared; no prompt appears on a non-terminal |
| admin CLI -> keyroster-server -> signer (revoke machine) | An admin-signed subject revocation, then a directory version; the CLI checks the served directory against its host-trust floor and the published KRL against the root-pinned bundle |
| the restore runbook -> a restored signer | Holds armed before the restore are lost or released; the re-run order puts the sweeps after the last lost version |
