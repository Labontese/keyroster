## The managed files (exact formats)

keyroster_known_hosts: one `@cert-authority` line per CA of hostTrustCAs, in its order, none when no principal is active; names are the principals of the active entries, sorted, unique, comma-joined; no plain keys, hashed names or wildcards.

```
# keyroster: managed file, rewritten by keyroster login and keyroster known-hosts sync. Do not edit.
# directory version N (sha256 <hex>), trust bundle version B, KRL version K (informational; never read back)
@cert-authority <active names, sorted, comma-joined> <CA key> keyroster host CA generation G
```

keyroster_ssh_config (with no names only the two comment lines):

```
# keyroster: managed file, rewritten by keyroster login and keyroster known-hosts sync. Do not edit.
# Include it from ~/.ssh/config before the first Host or Match line.
Host <every name in the state, sorted, space-separated>
	UserKnownHostsFile ~/.ssh/keyroster_known_hosts
	GlobalKnownHostsFile ~/.ssh/keyroster_known_hosts
	StrictHostKeyChecking yes
	UpdateHostKeys no
	VerifyHostKeyDNS no
	RevokedHostKeys ~/.ssh/keyroster_revoked_hosts.krl
```

keyroster_revoked_hosts.krl holds the verified KRL bytes. The state file host-trust.json is one JSON object with sorted unique names:

```
{"format":1,"installation_id":"<32 hex>","bundle_version":B,"ops_key":"<ops key text>","directory_version":N,"directory_sha256":"<64 hex>","krl_version":K,"names":["web1","web1.lab"]}
```

A name in the block without a CA line is refused, never prompted; GlobalKnownHostsFile also hides a system ssh_known_hosts for the block's names. Fail-safe argument (T-03-241, T-03-346): for a name in the block a host key is accepted only if a CA line lists the name under CA c, the certificate is signed by c, names the name and is valid, and the KRL does not revoke it; a name outside the block keeps the user's configuration. (M1) The block only grows. (M2) A KRL at or above the floor never un-revokes a live certificate: entries leave only after ValidBefore + 300, explicit keys never leave, a recovery only adds. Going from S to S' in the write order: after the state the files are S; after the KRL, accepted is a subset of accepted(S) by M2; after known-hosts, the name is in the old block, a subset of the new one by M1, and listed in the new CA lines, which is acceptance under S'; after the config the files are S'. A disabled or removed name loses its CA line at the known-hosts rename and stays in the block, so it is refused; an added name is outside the block until the config rename, as before the run. The next run converges because it re-verifies and re-derives everything. The older-bundle path is the KRL-only path (state, then KRL): it stops at "after the KRL", so the argument holds; M2 rests on the KRL floor, not on which key signed.

At the bound: write the KRL, keyroster_known_hosts and the state's versions; do not rewrite keyroster_ssh_config; warn on every run with the count of uncovered new names; `known-hosts sync` exits 3. New names then fall to the user's own configuration (their CA lines are inert, since ssh reads keyroster_known_hosts only inside the block). The remedy: delete the state and the three files (enroll-user.md). Dropping the oldest name would reopen TOFU silently; refusing the whole refresh would let an insider who churns signed names stop revocations (QB-1).
- **Missing, corrupt or foreign state (QB-3).** A missing state is a first run (floors 0, no names) only when none of the three managed files exists. Refuse every write, and say that revocations and names are not refreshed and which four files to delete, when: the state is missing while a managed file exists; it fails to decode, holds a bad name, is over the bound, is a symlink or is unreadable; or it carries another installation ID. Only local damage causes these; a silent reset would drop the floor and the names. State names get only the hostTrustName check, so a later tightening of the directory grammar never drops a recorded name; a failing state name makes the state corrupt.
- **Merge on write.** The state is written first as a merge: re-read just before its rename, union the names, take the maximum versions. If the merged state on disk is newer than this run's inputs, the run writes no managed file and says so. There is no lock file (no new syscall capability); concurrent runs cannot roll back below the floor the run began with.
- **Include placement.** Read ~/.ssh/config (at most 1 MiB, never written; larger is not scanned and the run says so). Keywords are matched case-insensitively with `Key Value` or `Key=Value`. No `Include` whose argument ends in `keyroster_ssh_config`: print `Include ~/.ssh/keyroster_ssh_config` once and "put it before the first Host or Match line". Such a line after a Host or Match line: warn with both line numbers (ssh keeps the first value it obtains, and an Include inside a Host block is conditional on it). Any keyword the managed block sets (StrictHostKeyChecking, UserKnownHostsFile, GlobalKnownHostsFile, UpdateHostKeys, VerifyHostKeyDNS, RevokedHostKeys) or KnownHostsCommand before the Include also warns: ssh keeps the first value. ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| keyroster-server → CLI | Directory, signatures and KRL arrive as untrusted bytes; the CLI verifies them itself against the root-pinned bundle and policy before any file is written |
| CLI → ~/.ssh | Three managed files and a state file; the user's own config and known_hosts are never written; every write is atomic |
| login redeem → CLI | The answer's directory is unauthenticated until the CLI verifies it; a miss or a forgery never costs the login |
| admin → signer (revoke host, loss revokes) | One admin signature revokes, in the fail-safe direction; the disable needs quorum |
| user's ssh → managed Host block | Only exact principals under the host CA, minus the KRL, are accepted for any name the CLI ever saw; names outside the block keep the user's configuration |
