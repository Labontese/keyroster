## Planner decisions (Claude's discretion), recorded with their reasons

- **D1. Five tasks and a single plan.** Tracer; reporting; the decision (classify, state, budget, account, gate, hold); the probes in forward with the full e2e; the gates, PR and SUMMARY. The seam cannot be split off: once the gate is mandatory every existing e2e and distro test needs it in the same PR (the 03-10 tracer argument).
- **D2. The gate runs before allocGeneration.** Classification and every gate input need only the candidate and files in memory or on disk, so a held retry writes no generation (it runs every 60 s). Only the intermediate that a hold lands is installed.
- **D3. The seam is an unexported field.** `Config.probeOff` is set by `newTestHostIn` in package apply and by one exported setter, `DisableProbes`, that exists only in internal/agent/apply/probeoff_e2e.go (tag below). cmd/keyroster-agent/probeoff.go (default build) refuses `--probe-self-test off`; probeoff_e2e.go sets it. No external package can set the field in a default build, so the zero value fails closed. <!-- planner-discipline-allow: keyroster_e2e --> The tag is `keyroster_e2e`.
- **D4. The probe principals file is rendered only with probes on, by the agent.** `probeFileFor(host)` lives in internal/agent/apply/probe.go; with probes off no file is added, so every generation of the existing unit, e2e and distro tests stays byte-identical. A host group that maps the probe account itself keeps its file untouched and the gate holds `account_is_managed`.
- **D5. A pair is requested whatever the account's state.** The issuance step applies only the host-level holds of hostcert.HostHold, so a pair is ready the moment an operator creates the account; the cost is two leaves per host per lifetime.
- **D6. The e2e machine cap is 600 s.** The usable window of a pair is L minus the missing margin minus the widening wait (33 s) minus two self-test timeouts; renewal starts at 2L/3 minus jitter. At 600 s the window (about 485 s) covers the test's three widenings (about 250 s) with no renewal; renewal is unit-tested with the fake clock. A 90 s cap would leave no usable pair for a widening.
- **D7. The gate looks ahead.** Pair validity and the 60 s spacing are evaluated at `now + remaining wait` (and at probe time again, sleeping on the fake-able clock if the spacing is not yet met), so the cost of a widening step is its wait, not its wait plus the spacing.
- **D8. Opportunistic probes after a narrowing change are in scope** (design section 3.6): they are the only way a host whose sshd ignores revocations is noticed between additions. At most one per 10 min and never when 3 negatives were sent in the last hour, so half the hourly budget stays free for additions.
- **D9. The held retry uses Run's existing Retry (60 s)** and a new pair triggers an apply at once while a hold exists. Identical consecutive held errors are logged once per 15 min.
- **D10. A failure key.** A rolled-back addition records SHA-256 over the candidate's classified content, both pair serials and the account's passwd line; the retry waits 60 s doubling to 1 h while the key is unchanged and is immediate when any input changes.
- **D11. One record file.** <state>/probe.json holds the pairs (certificates inline, base64), the two attempts and the step's last detail; <state>/probe-state.json holds the gate's state. Two files, one writer (the applier, under apply.lock), no subdirectory.
- **D12. The two new e2e tests are `t.Parallel()`, both, as their first statement.** Go resumes parallel top-level tests only after every serial test of the package has finished (no existing test in test/e2e calls t.Parallel), and only these two are parallel, so the one package variable they touch, the machine-cap global of bootstrap_test.go (the pattern of `genesisHostMaxTTL`, which says the e2e tests run one at a time), is read and cleared by TestProbeSelfTestEndToEnd alone while TestProbePairSpacing starts no server. Task 4's verify counts `t.Parallel()` (exactly 2 in probe_selftest_test.go) and the uses of the global (only bootstrap_test.go and probe_selftest_test.go). If the executor finds a reason that makes this unsafe, the tests run in series, the lane is expected at about 415 to 465 s against the 420 s cap, and the two-pair fallback of Budget and verify is applied first.
- **D13. A failed gated addition rolls back the addition only (Plan check 1, sec-rollback-regrants-removal).** 03-05's rollback restores last-good wholesale (RollbackTarget, render.go:435-449, via backToLastGood, apply.go:1520-1556), which re-grants the removal part of a mixed change. For a target gated as a widening, a probe or served-certificate failure therefore moves current to the intermediate Transition installed for that change (`settleFailedAddition`, Task 4) and commits it; the settled content is always `Intermediate(lastGoodGen, final target)` with the target's newest KRL (Fix round 3, r2-1): plain rollback is taken when that collapses (nothing last-good grants was removed by the final target), the generation that was live just before the widening swap (the forward-local `preN`, never Report.Intermediate, which every Transition-loop pass overwrites, apply.go:963-964) is used when its content equals it, and otherwise the intermediate is installed afresh (Fix round 2, settle-predicate-after-supersede).

## Contracts frozen by this plan

**Names.** Outbox `probecert-positive.req` and `probecert-negative.req` (hostcert.OutboxRequest JSON, at most hostcert.MaxOutboxRequest bytes, mode 0640 through writeFile); spool answers `probecert-positive.answer` and `probecert-negative.answer` (hostcert.Answer JSON, mode 0644, at most hostcert.MaxAnswer). `probe.RequestFileRE` is `^probecert-(positive|negative)\.req$`, `probe.AnswerFileRE` the same with `answer`; the spool prefix constant is `probecert-`. State files: <state>/probe.json and <state>/probe-state.json (mode 0600, owner the effective uid, a regular file, at most 16 KiB, canonical JSON, strict decode; anything else is unreadable).

**probe.json** `{"version":1,"committed":P,"next":P,"attempts":{"positive":A,"negative":A},"detail":"..."}`; P is `{"positive":C,"negative":C}` with either member null; C is `{"serial","issued_at","valid_before","renew_at","ca_sha256","key_sha256","cert"}` (cert is the SSH wire certificate, base64; key_sha256 is the lowercase hex SHA-256 of the probe public key's wire encoding; issued_at = ValidAfter + 300; renew_at drawn once by hostcert.RenewAt when the certificate is kept); A is `{"requests":[{"id","created_at","consumed","probe_key"}],"failures","next_at","last_code","sticky"}` with at most hostcert.MaxPending requests, `probe_key` the public key (base64) of that request, `sticky` the hostcert.StickyHold shape.

**probe-state.json** `{"version":1,"negatives":[u64],"last_pair","last_opportunistic","failure":F,"alarm":"","held":H,"reset_at"}`; `negatives` are the Unix seconds of the negative probes sent in the last hour (at most 16 kept); F is `{"code","key","at","count"}`; H is `{"reason","bundle","directory","krl","at"}`; `alarm` is the last unresolved code of an opportunistic probe.

**Closed sticky refusals** (a refusal detail from the signer or the server that holds a polarity until the accepted bundle, policy or directory version changes or 24 h pass; hostcert.StickyReleased): host_key_not_enrolled, host_name_mismatch, signer_too_old, malformed_request, unknown_host, host_key_not_listed, host_key_revoked, host_disabled, host_pop_not_enabled, probe_issue_no_installation_id, probe_issue_installation_mismatch, probe_issue_valid_for_not_zero, and `http_<4xx>` other than 429. Transient with the back-off: request_time_skew, directory_changed, trust_changed, probe_cert_recent, duplicate_request, host_pop_invalid, probe_pop_invalid, probe_key_unusable (a fresh key per request makes each of these a one-attempt failure), ca_not_configured, directory_not_installed, directory_not_authorized, state_unavailable, serial_unavailable, clock_regression, krl_too_large, krl_no_installation_id, revocations_not_logged, the 5xx and transport errors (no answer: abandoned after hostcert.RequestTTL as `no_answer`), and every detail not named.

**Closed codes.** Gate hold reasons: cert_missing, issue_unanswered, issue_refused, positive_in_krl, negative_not_in_krl, ca_mismatch, account_missing, account_unparsable, account_uid_zero, shell_missing, shell_not_nologin, account_is_managed, failure_backoff, budget (03-10c adds password_set, password_empty, account_excluded, sshd_override). Details: `probe_held:<reason>`, probe_positive_refused, probe_krl_not_enforced, probe_inconclusive, served_cert_mismatch, probe_state_reset, probe_self_test_off, and the step's `probe_issue:<code>` (the hold or defer code with ':' replaced by '_'). Report values for probe_positive and probe_negative: pass, fail, inconclusive, skipped:<exempt_first_install|exempt_trust_only|exempt_probe_file_only|budget|not_ready|off>. Every detail is at most 64 bytes of ^[a-z0-9_]+(:[a-z0-9_]+)?$; the longest is `probe_issue:refused_probe_issue_valid_for_not_zero` (50 bytes).

**Classes** (computed by `classify(lg, cur, g, account)`): first install (no last-good, or no current), trust-only (g holds no principals file), narrowing (`isNarrowing(cur, g)`; the KRL may change), probe-file-only widening (the only thing g adds over cur is the probe account's generated file: principals/<probe account> counts as unchanged only when g's bytes there satisfy `isProbeFile` with g.Host and cur's file is absent or satisfies `isCurProbeFile` (the generated form, or the intermediate-header form that a hold or a settle leaves: the header with no principal line, or with exactly the probe line); any other content at that path, a mapped account's role file included, is compared like any account), widening (anything else, a mixed change included). `isProbeFile(b)` accepts exactly the three-line format below and nothing else, so a probe file with an extra principal line, or a directory-rendered file, is not one. `isCurProbeFile(b)` is used for cur's side only and also accepts the intermediate form: exactly the intermediate header line (render.go:32) alone, or that header followed by exactly one line `keyroster-probe:<name>`.

**Probe principals file** `probeFileFor(host)`: line 1 `# keyroster: generated AuthorizedPrincipalsFile; do not edit`, line 2 `# probe account, host <name>`, line 3 `keyroster-probe:<name>` (cert.ReservedPrincipalPrefix plus the entry name).

- **`BuildRequest(host ssh.Signer, installationID, hostName string, negative bool, now time.Time, rnd io.Reader, keygen KeyGen)`** with `type KeyGen func(io.Reader) (ed25519.PublicKey, ed25519.PrivateKey, error)` returns the wire.ProbeIssueRequest and the probe public key.
