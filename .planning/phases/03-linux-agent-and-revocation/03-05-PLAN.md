<objective>
Build the agent's apply engine, the place where lockouts happen, and prove it offline against real sshd before any network code exists: signed state in, verified against the agent's own pins, rendered into an atomic generation, checked with the host's own `ssh-keygen` and `sshd -t`, swapped, reloaded only when needed, self-tested, rolled back on failure.

Purpose: AGENT-04 (atomic write, sshd -t, reload, self-test, rollback), AUTHZ-02 (principals files from the signed directory, through the one renderer), REVOKE-03 (atomic install, last-good, rollback refused, no lockout from a bad KRL). The sshd re-read behaviour the whole design rests on is pinned by a test on both CI OpenSSH versions.

Output: packages internal/agent/{state,spool,apply,paths}, the `keyroster-agent` binary (applier only; the fetcher is 03-07), two e2e tests, the dependency firewall generalised per binary, a capslock baseline, and a PR.

**Owner decision before implementation: D-05 against D-06 (Task 1).** D-05 gives the root applier no network access; D-06 requires a self-test that talks SSH to the host's own sshd after every apply. Taken literally they collide: the research's unit for the applier (`PrivateNetwork=yes`) leaves it a namespace with only its own loopback, from which the host's sshd cannot be reached. The first draft of this plan settled that as Claude's discretion; because it reinterprets a locked decision and shifts the threat model, the owner decides it in Task 1, before any applier code exists, and 03-06, 03-07, 03-08, 03-09 and 03-10 check the recorded answer instead of presuming it. Tasks 2-4 are written for the recommended answer, `loopback-only`: "no network access" then means no route off the host and no HTTP, TLS or RPC code; the unit (03-08) sets `IPAddressDeny=any` and `IPAddressAllow=localhost`; the code dials only loopback addresses, and only for the sshd self-test (and the 03-10 probes); a host whose sshd listens on no loopback-reachable address is refused with an explanation (03-06 adds that check to the D-07 refusals). Whether any dogfood host's sshd listens only on a tailnet address is not recorded (the 02-14 SUMMARY and host-setup.md contain no ListenAddress); 03-16's preflight shows it.

**Spool format (Claude's discretion: the fetcher/applier IPC).** A directory of files written atomically by the fetcher (03-07) and read by the applier: `bundle-<v>.json`, `bundle-<v>.json.sigs`, `policy-<v>.json`, `policy-<v>.json.sigs`, `directory-<v>.json`, `directory-<v>.json.sigs`, `krl-<v>.krl`, `krl-<v>.manifest.json`, `krl-<v>.manifest.sig`; size-capped per kind; unknown names ignored and reported. Data only, never commands: the applier treats every byte as untrusted and re-verifies it.
</objective>

**internal/agent/state.** `Pins{TrustPins []string json:"trust_pins"; Threshold int json:"threshold"; InstallationID string json:"installation_id"}` (canonical JSON, file `<state>/pins.json`, root 0600; refuses empty pins, threshold < 1, empty or malformed installation ID). `Stored{Bundle, BundleSigs, Policy, PolicySigs, Directory, DirectorySigs, KRL, KRLManifest, KRLSig []byte; BundleVersion, DirectoryVersion, KRLVersion uint64}` persisted as files under `<state>/accepted/`, written atomically. `Verify(p Pins, prev *Stored, in spool.State) (*Verified, error)`:
- bundle: with no stored bundle, the newest offered bundle must pass the serverclient.Trust rule (its root set matches the pins at the threshold, self-signed by that threshold, policy hash) and carry `InstallationID == p.InstallationID`; with a stored bundle, every offered bundle above it must be the next version by trust.VerifySuccessor, applied in order; a gap or an older version is refused (`bundle_chain_gap`, `bundle_older`); equal is a no-op.
- directory: verified against the policy in force (directory.VerifySignatures, CheckPolicy), installation_id equal to the pin (`directory_installation`); with a stored directory, the next ones must pass CheckSuccessor in order; with none, the newest offered standalone.
- KRL: krl.VerifyManifest(manifest, sig, krl, bundle, p.InstallationID, prev.KRLVersion), then krl.Parse; equal version is a no-op.

**internal/agent/spool.** `State` (the files listed in the objective), `Read(dir) (State, []string unknown, error)` with per-kind caps (bundle and policy 1 MiB, directory directory.MaxDirectory, KRL krl.MaxKRL), `Write(dir, State)` for the fetcher (03-07) using temp files in dir and rename.

**internal/agent/apply.**
- layout.go: `Layout{Root, StateDir string}` with methods for every path above; the drop-in path is `<Root>/etc/ssh/sshd_config.d/00-keyroster.conf`.
- render.go: `Render(v *state.Verified, hostKeys []ssh.PublicKey) (*Generation, error)`: finds the host entry with HostForKey for any host key (all matches must name the same host, else `host_keys_disagree`), refuses a disabled or absent host (`host_not_in_directory`), renders user_ca_keys (active and next entries of roles user and machine, sorted by role then generation) and principals for each account of the host's group, and carries the KRL bytes.
- validate.go: the pre-swap checks in must_haves through sshd.go's exec helpers.
- sshd.go: the only exec sites, each with fixed argv and absolute binary paths taken from the Config: `sshdTest(bin, cfg)` = bin -t -f cfg; `sshdDump(bin, cfg, spec)` = bin -T -f cfg [-C spec]; `keygenFingerprint(bin, file)` = ssh-keygen -l -f file; `keygenQuery(bin, krl, pub)` = ssh-keygen -Q -f krl pub; `reload(strategy)` for the closed set `signal` (SIGHUP to the pid read from the pidfile `sshd -T` names; no exec), `systemd:<unit>` (/usr/bin/systemctl or /bin/systemctl reload <unit>, the unit name validated against `^[a-z0-9@._-]+\.service$`) and `openrc` (/sbin/rc-service sshd reload). Output of every exec is size-capped. 03-06 adds detection; here the strategy comes from the command line.
- swap.go: generation directories created with a temp name in gen/ and renamed to N; `current` and `last-good` swapped with a temp symlink and rename(2); fsync of the directory and its parent after each; a generation that `current` or `last-good` names is never deleted; older generations beyond the newest 5 are removed.

- apply.go: `Apply(ctx, cfg Config, layout Layout) (Report, error)` with the sequence of must_haves, the flock on `<state>/apply.lock`, and crash recovery from `<state>/pending.json`. Report is JSON: versions applied, generation, reloaded (bool), self-test result, rollback (bool), errors.
