## The fixed test, and what it must assert

TestHostCARotation, on one enrolled host whose host certificate cap is 90 s (`withGenesisHostMaxTTL(t, 90*time.Second)`, as test/e2e/hostcert_test.go:398 does) and the default user cap (so the 1 h role and `issueAgentCert`'s 10 min certificates work), with the server's stoppable signer, PoP hosts and the agent listener, and no `t.Parallel` (the genesis caps are package globals, bootstrap_test.go:66). Each step's assertion is fixed; its bounds are taken from the previous issuance, never as "so many seconds from now":
1. **Genesis.** The host's first certificate c1 is signed by host CA generation 1 (`keyscanCert`, hostcert_test.go:151, returns the certificate sshd serves). A real `keyroster known-hosts sync` (the CLI's own path, with a real HOME as `requireRealHome`, hosttrust_test.go:57, gives it) writes exactly one `@cert-authority` line for the host. A copy of that managed file is kept for client B, which never refreshes; client A keeps the live one.
2. **Prepare and ceremony 1**, inside c1's quiet window (renewal falls 51 to 60 s after issuance at a 90 s cap, internal/agent/hostcert/hostcert.go:551-569, so both stop windows end before c1 plus 51 s): prepare `--role host --key <fp2>` with the signer stopped, ceremony 1 with `--ca-next host=... --ca-next-fingerprint host=<fp2>` (the display names `CA host gen 2 <fp2>: none -> next`), the install with the signer stopped, and the host's heartbeat reporting bundle 2 committed within a bound of its own.
3. **Refresh A.** `known-hosts sync` now writes two host CA lines (generation 1 and generation 2). A and B both log in (the control for B's later refusal). The export for ceremony 2's `--previous` is taken after ceremony 1's install.
4. **Anchor on a fresh renewal.** The test waits for r1, the renewal signed by generation 1 (bounded from c1's issuance as hostcert_test.go:408 bounds a renewal, 51 to 75 s), then runs ceremony 2 at once with `--ca-switch host --drain-allowance 60s` (never 0: the agent asks for certificates by itself), so no renewal request falls into a stopped-signer window, where a failed renewal near the end of a 90 s certificate costs a 60 s back-off (hostcert.go:592-593) and lets it expire.
5. **The switch**, with the signer stopped and a stop check at the bundle's issued_at plus 50 s: install with `--previous` (the drain line with v plus 300 s at or below t); serve refuses `draining_key_still_usable`; retire-key `--role host` and the printed `ssh-add -d` through the parameterised `caRotRetireKey`; the agent no longer lists the key; doctor prints no `draining_key_still_usable`; serve again.
6. **The old key still serves.** Right after serve: `keyscanCert` shows generation 1, A logs in, `keyscanCert` shows generation 1 again, so A's login provably met a generation-1 certificate; B logs in too, which shows that B's failure comes with the renewal and not with the switch. Only then the heartbeat of bundle 3 is awaited.
7. **The renewal under the new key.** r2, bounded from r1's issuance, is signed by generation 2, and sshd serves it.
8. **After the renewal.** A logs in. B is refused with `Host key verification failed`, from a loopback source of its own (OpenSSH 10.x PerSourcePenalties; the house pattern gives each refusal its own source), offering the certificate algorithms only. Optionally, B refreshes and logs in.
9. **Audit and the lane's line.** `audit verify` of a fresh export passes and names bundle v3; the test logs one fixed line, `host CA rotation: the refreshed client accepted generation 1 and generation 2, the client that did not refresh was refused`, which the lane gate greps.

The test does not wait for the host drain (trusted_until is about issued_at plus 90 + 300 + 60 s), so the narrowing never touches the generation-1 line during the test. A host-only bundle change renders identical `user_ca_keys` on the hosts, because host CA keys are never rendered into a host's own files (internal/trust/castate.go:102), so the host's own trust files are not evidence of the switch; the heartbeat's committed bundle is.

## Timing facts and the budget

- **The test:** about 120 s at least (setup of about 15 s, then two renewal cycles of at least 51 s each from c1), about 130 to 150 s typically (TestHostCertRenewAndRestart, setup plus two renewals at a 90 s cap, took 133.15 s and 129.48 s in CI), about 220 s for the slowest passing run (first certificate within 60 s, each renewal within 75 s of the previous issuance, heartbeat commits within 45 s, overlapped), and about 330 s when it fails at every bound.
- **The lane today:** `go test` 531.194 s (9.5p1) and 530.654 s (10.5p1) on main at 2ed959f (E2E run 44661169390), 525 to 534 s over five heads; TestCARotationNoFailedLogin 467 to 472 s of it. With this test a passing run lands at about 650 to 755 s, a margin of at least 145 s against the owner's 900 s, and a run failing at every bound at about 865 s, under 900 s and under `-timeout 20m`. It fits: no lane of its own, no shorter cap and no shared setup are needed.
- **Fetchers poll every 5 s.** The host-certificate fetcher of the host e2e polls every 5 s (`hostCertPoll`, hostcert_test.go:26); the server limits each agent to 30 requests a minute with a burst of 64 (internal/server/agent.go:43-44), and a fetcher at 1 s stalls a long test (03-12e2's deviation 9). The test uses `joinHostCert` (hostcert_test.go:51), never `joinApproved` or `startEnrolled`; host-status loops run at 2 s.
- **Helpers and short profiles.** The test keeps the default user cap, so `enrollApproved` (a 1 h role) and `issueAgentCert` (10 min) work; any goroutine uses error-returning helpers (03-12e2's `loopIssue` and `loopLogin` are the pattern), never a helper that calls `t.Fatalf` from a goroutine.
- **The 900 s rule is machine-checked** from the PR run's logs with 03-12e2's lane gate (its Task 4, second verify command), extended to `--- PASS: TestHostCARotation (` and the fixed log line, with `login failures: 0` of TestCARotationNoFailedLogin still required. Above 900 s the executor stops and reports; no timeout is raised.
- **The main e2e lanes must not compile the test**: a `head -1` gate requires the file's first line to be exactly `//go:build e2e && e2erotation`, and the main lanes' times are compared with their base.
