<objective>
The signer issues, logs and bounds machine certificates by proof of possession of the machine's own key against an admin-signed directory entry, `audit verify` re-proves each one, and `revoke machine` works in the signer and in audit. This is the part of machine identities that is costly to reverse, planned and reviewed on its own (OQ-1) before the first anonymous route depends on it.
- A request (frame 0x0C) carries the installation ID, the machine name, the machine key, valid_for 0, a request ID, a time and one machine-pop/v1 signature by the machine key. The signer decides from the directory alone and issues a user-type certificate from the machine CA with exactly the principals of the machine's roles, the lifetime it chooses, and a kr3 key ID, after its `machine_issue` leaf (kind 13) is committed.
- The identity checks come first and use the listed key, so no state fact (disabled, revoked, held, rate-limited) is decided for someone who has not proved the key. A `revoke machine` leaves two holds that stop re-issuance until a newer directory version, one on the key's latest certificate and one on the machine's name (derived from the logged subject revoke, so it arms for an idle machine and for a key with only kr1 certificates too), so a pending disable (admin quorum above 1) does not let a stolen key renew.
- 12 renewals per machine key per hour; a refusal bucket of its own; the machine index rebuilt from the log; audit re-proving every rule with the same shared functions.
- New directories cannot name a machine `probe.*` or give a machine more than 32 principals; a subject revoke of kind machine resolves the machine's live certificates and never a probe certificate.

Purpose: the signer half of **AUTH-06** (D-15) and **REVOKE-01** (D-09); both complete in 03-11b.

Output: Task 1 the formats and the tracer (one machine renews at the signer socket, logged, restarted, re-verified by audit); Task 2 the hold, the bound, the unusable-key rule, the index's revoke handling, the classified refusals, the bucket and audit's matching rules; Task 3 the reservations and the signer and audit side of `revoke machine`; Task 4 the tracking edits, the gates, the PR and the SUMMARY.
</objective>

## Planner decisions (Claude's discretion), recorded with their reasons

- **PD1. Four tasks, tracer first.** Task 1 is a tracer: one machine request through every layer this plan touches (wire, tlog, registry and vectors, directory grant, cert lifetime, signer, log, restart, audit, export). Tasks 2 and 3 expand it. Task 4 is tracking, gates, the PR and the SUMMARY; the owner's merge follows it (`autonomous: false`).
- **PD2. The machine index is its own file** (`machineindex.go`, on the pattern of hostindex.go) and a field of loggedInstalls, rebuilt by rebuildLogFrom and staged in `pendingMachines` and installed only after COMMIT, as pendingHosts is. It is applied at the same four sites in logstate.go: the field and its clone, the rebuild, appendLocked and logTx (including both nil-reset lines). The explicit-key set `s.loaded.hosts.revokedKeys` already records every RevokedKey entry of any CA (hostindex.go:214-217) and is reused, not copied.
- **PD3. Recovery-carried certificates and the bound.** A kr3 `ca=machine` certificate that a recovery carries and that is not a probe certificate (`!krl.IsProbeKeyID`) becomes the latest certificate of its key when its serial is above the indexed one (the hostindex.go:153-178 rule), marked revoked when the recovery revokes it, and does not count toward the 12 per hour, because its issuance belongs to a log that was lost. The signer's index and audit's mirror apply the same rule in the same order, and a test pins both.
- **PD4. The bound's input and its one list rule.** The input is the issuance second ValidAfter + 300 in the index rebuild and in audit, and the signer's clock at the request before a serial is drawn. A certificate counts toward a later request while its issuance second plus 3600 is above that request's second (a clock stepped back is counted, the safe side). The list has one rule for both sides: `cert.MachineRecentAdd(recent, issued)` appends `issued`, drops every second that is 3600 or more below the largest second in the list, and keeps the twelve largest by value, ascending, returning a new slice. The signer's index and audit's mirror call it on the same sequence of leaves, so their lists are identical by construction, also after a clock step back (fix round 2, hold-06). The signer decides with an earlier or equal second than audit uses, so a leaf the signer wrote always passes audit's re-derivation.
- **PD5. `machine_name_reserved` is also refused at issuance,** in the global block, because a directory stored before the install-time rule may hold a `probe.` machine, and a certificate with `sub=probe.<name>` would read as a probe certificate in recovery and audit. The refusal reveals nothing about identity (it depends on the request's own text). Audit fails such a leaf.
- **PD6. One lifetime function.** `cert.MachineLifetime(grantMaxTTL, profile)` is min(the grant's TTL, the profile's cap in whole seconds); MachineGrant's TTL is already min(the entry, every role). The signer and audit both call them, so `min(entry, roles, machine cap)` has one implementation.
- **PD7. Wire fuzzers sit in machineissue_test.go,** as probeissue_test.go holds the probe ones, so wire/fuzz_test.go stays unchanged (the design note listed it).
- **PD8. Audit's request-ID checks for the older kinds sit in verify.go.** The signer's `RequestIDUsed` is one table across all issuing kinds, so audit must refuse a reuse in either order. The checks of issue, login, host and probe are added at their existing dispatch sites in verify.go, and audit/hostissue.go and audit/probeissue.go stay unchanged.
- **PD9. Test cost.** The signer package is the 90 s delta risk. The signer tests share one environment per group where the state allows (the refusal subtests of TestMachineIssue share a ready environment and a request builder), and only the bound, the restart and the recovery tests issue many certificates. Every subtest builds its own state from the shared constructor and passes when run alone (`-run '^TestA$/^case$'`), because mutants are run on one subtest; no subtest relies on a predecessor.
- **PD10. No re-delivery.** Unlike hosts, a machine request that the latest certificate answered is not re-served: the CLI is one-shot (default 10).
- **PD11. The name hold (default 2 amended, 2026-11-10; plan check 1).** *Why:* the key hold arms only when a revoke entry names the key's latest indexed certificate, and a subject sweep lists live certificates only (signerdb/revocation.go:162, `krl.EntryLive`), so at admin quorum above 1 a thief could renew during the pending disable when the latest certificate had expired, when the live certificates were kr1 only, or after a re-listing. *Rule:* every logged `revoke` leaf whose request is TargetSubject with SubjectKind machine and subject S sets `nameHeld[S]` to the directory version in force at that leaf, and MachineIssue refuses `cert_revoked` for entry name S while the directory version in force is not above it, whether or not the sweep listed any certificate (a zero-entry subject revoke still writes its leaf, signer/revoke.go:119-145). *Derived* from the leaf's logged request (`wire.ParseRevokeSigningBytes`) in the machine index's revoke arm and in audit's mirror, so a restart rebuilds it from the log and no table is scanned; a request that does not parse is ignored there (audit's own revoke rule judges it). *Order:* after the proof of possession (default 1) and after `machine_disabled`, so a disabled entry reports `machine_disabled`, the stronger and lasting fact. *Release:* any newer installed directory version; an equal one still holds. *Keep-first:* not applied to the name hold. It moves to the version of the latest logged subject revoke of S, which is safe because `machine_disabled` is checked first, so a second sweep after the disable cannot mask it; the key hold keeps keep-first. *Rename:* a rename needs a new directory version, which releases any hold, and the new name has none; the key hold follows the key; certificates issued under the old name are not swept by `revoke machine NEWNAME` (03-11b's row, T-03-72). *Residuals:* a restore of the signer state loses name holds armed by lost subject revoke leaves (a zero-entry subject revoke is in no KRL), so after a restore `revoke machine` is run again for every machine whose disable is still pending; a subject revoke logged after a name was re-added with a new key holds that new key until a newer directory version, so sweep before re-adding. *One rule:* the name hold calls `cert.MachineCertHeld` with a prev built from `nameHeld[S]`, so signer and audit share it.

## Formats this plan freezes (the registry rows follow them)

**MachineIssueRequest** (internal/wire/machineissue.go, as hostissue.go). Constants: `MachineIssueRequestDomain = "keyroster/machine-issue-request/v1"`, `MachinePoPNamespace = MachineIssueRequestDomain`, `EvidenceMachinePoP = "machine-pop/v1"`; frame `TypeMachineIssueRequest byte = 0x0C`, answered by `TypeIssueResponse` 0x81 and capped at MaxFrame. Fields: InstallationID (trust.IsInstallationID), MachineName (the directory name grammar `^[a-z0-9][a-z0-9._-]{0,63}$`; a test pins equality with `directory.ValidUserName`), MachineKey (canonical SSH wire form of `ssh-ed25519`, `ecdsa-sha2-nistp256/384/521`, `sk-ssh-ed25519@openssh.com` or `sk-ecdsa-sha2-nistp256@openssh.com`; never RSA, never a certificate), ValidForSeconds (uint32), RequestID (16 bytes, non-zero), CreatedAt (non-zero Unix seconds), Evidence (exactly one item). Signing bytes: the raw domain, then InstallationID, MachineName and MachineKey (uint16 length each), ValidForSeconds (uint32), RequestID, CreatedAt (uint64). Marshal is the fields without the domain, then the evidence as HostIssueRequest does. The evidence is a `machine-pop/v1` armored SSHSIG by MachineKey under `MachinePoPNamespace` over the signing bytes. Validate puts no rule on ValidForSeconds or on whether the key is the listed one: the signer refuses those with classified details. `Digest` is the SHA-256 of the signing bytes; `ParseMachineIssueRequest` and `ParseMachineIssueSigningBytes` are strict.

**Leaf kind 13 `machine_issue`** (`tlog.MachineIssueBody`, its own type so that a confusion with HostIssueBody fails to compile): Serial, PolicyVersion, DirectoryVersion, CapSeconds (= the lifetime L the signer chose), Request (the signing bytes), Evidence, Cert, KeyID, encoded and decoded as HostIssueBody is (strict, trailing bytes refused). `Kind.valid()` becomes 1 to 13, 15 and 16 (14 stays 03-12's).

**The certificate.** CertType user; CA the active machine CA (`s.ca[wire.CARoleMachine]`); principals exactly the sorted union of the machine's roles' principals; key ID `kr3/ca=machine/sub=<name>/req=<request id hex>/pol=<policy version>/dir=<directory version>/ser=<serial>`; ValidAfter = issuance minus 300 s; lifetime L = min(entry max_ttl_seconds, every role's max TTL, machine cap in force) in seconds, which is the leaf's CapSeconds; extensions the profile defaults plus the roles' extensions; no critical option.

**Refusal details this plan adds** (each classified, with a wire-code assertion): `machine_issue_no_installation_id`, `machine_issue_installation_mismatch`, `machine_pop_not_enabled`, `unknown_machine`, `machine_key_mismatch`, `machine_pop_invalid` (class Unauthorized, code refused); `machine_key_revoked`, `machine_disabled` (Unauthorized); `machine_key_unusable` (BadSubjectKey); `machine_issue_valid_for_not_zero` (TTLExceeded); `machine_renew_too_often` (DuplicateRequest); `machine_name_reserved`, `machine_principals_exceed` (Unauthorized); `subject_reserved` (Malformed, code malformed). ## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| holder of a machine key (automation host) -> signer socket (through keyroster-server, 03-11b) | A request crosses it; the signer decides from the admin-signed directory and one proof of possession by the listed key, never from the server's word |
