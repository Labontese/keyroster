<objective>
The readers of the rotation (D-14, KEY-08): bundles can carry a `draining` CA with an end date, every agent trusts it until that date and then drops it by itself, without another bundle and without ever taking it back; the agent also notices when the server withholds a bundle.

Purpose:
- **The format.** `draining` and `trusted_until` parse everywhere, are validated in one place and printed to the root holders, so 03-12e can make its switch produce them with every reader ready.
- **The drop.** The host decides on its own clock. A timer applies at the end date, the line leaves through the one narrowing path, and a permanent latch keeps it out against a backward clock step, a rollback and a directory reset.
- **The same rule everywhere an agent decides who may answer.** Host certificates, probe pairs and the adoption of a Phase 2 host read the same time-aware set, and a kept host certificate of a draining CA stays until it is due.
- **The freeze.** A server that withholds the switch bundle leaves a host trusting the old key with no end. The ops key signs every KRL manifest and names the bundle version, so a host can see that it is behind; this is detection, which the owner chose over a lease.

## Planner decisions (Claude's discretion), recorded with their reasons

- **The genesis refusal is in Validate, not in VerifyGenesisBundle.** The agent's first acceptance (internal/agent/state/verify.go:605) runs trust.VerifySelfSigned and MatchPins and never VerifyGenesisBundle, so a refusal there would miss every agent. Validate already holds the version-1 rule (bundle.go:157-159), so the new one sits beside it: a version 1 bundle has no draining entry. VerifyGenesisBundle refuses it too, because it parses through Validate. The early plan listed internal/trust/verify.go; it is not edited.
- **`UserCAKeysFile` returns `([]byte, error)`.** renderTrust returns an error today when a CA key does not parse (render.go:293), and the portable helper must not skip a key silently, because a skipped key narrows. `UserCAKeysFileExcept(b, t, skip)` is the same function with a predicate for entries to leave out; the agent passes its latch, the CLI plans pass none.
- **The render takes a `RenderAt` struct.** `Render(v, hostKeys, at RenderAt)`, `RenderFallback(v, hostKeys, lastHost, lastGood, refusal, at RenderAt)` and `renderTrust(v, at)` carry the engine's clock and the latch's predicate (`RenderAt{Now time.Time; Dropped func(trust.CAEntry) bool}`) so that the latch does not cost a second signature sweep. The two production call sites are apply.go:1290 and :1347; the four test call sites are interleave_test.go:413, :617, :621 and :834.
- **The pending narrowing is defined on draining entries only.** The trigger of forward's no-op (apply.go:934) and of `trust_expired` is: current's `user_ca_keys` holds a line whose key is a draining user or machine entry of the accepted bundle that the render at now omits (its end has passed, or the latch holds it). The early plan's general wording (a line the render no longer holds) would also fire for a kept rollback state that holds an aborted key's line (03-10d, 03-12b), which has its own path; a held `next` line, which current lacks, is never a trigger. The gate reads current only when the accepted bundle has a draining entry, so every existing bundle takes exactly its old path.
- **The latch is recorded where the render omits the key, before anything lands.** `engine.render` (apply.go:1289) calls the recorder after a successful Render, never in `--dry-run` and never from Check; the write is spool.WriteFileAt through `e.writeState` (atomic, fsynced, mode 0600), so it precedes the marker, the generation and the swap (an injected crash at the marker still leaves it). A failed write aborts the apply before any swap: nothing is dropped without being recorded. An unreadable latch (present but not a 0600 regular file of the applier's uid, or not strict canonical JSON, or above 64 KiB) is read by the same checks `probe-state.json` uses (heldPending, run.go:312), is never overwritten or removed by the agent, and makes every draining user or machine entry count as latched. A missing file is an empty latch.
- **The latch covers the user and machine roles only.** Those are the roles of `user_ca_keys`. The host role's draining keys are in no file the agent writes; their end only changes the answer set and Due, which Task 3 makes time-aware, and the host-certificate step runs after every applied round and every check, so TrustDue covers all three roles (an apply at a host CA's end changes nothing on disk and then runs that step).
- **TrustDue is computed once, in Apply's epilogue.** `Report.TrustDue` (json:"-") is the earliest trusted_until after now of the accepted bundle (user, host and machine roles), read from accepted/ after the run, so every return path of forward, the early no-op return (apply.go:934-951) and held passes included, carries it. An apply that returns an error clears it, because Run's retry (`failedAt`, Retry) already governs the next attempt and a stale past TrustDue would make every 5 s iteration apply.
- **Check reports and never writes.** `DriftReport` gains `Draining`, `TrustExpired`, `TrustLatch` and `BundleBehind` (omitempty); `Drift()` is unchanged (OQ-D). Run's check closure (run.go:195-211) sets forceApply when TrustExpired is not empty, logs one `ERROR trust_expired` line per check while it is, and the first apply that follows heals an operator's `--recover-to-last-good` within one check period (03-12c's `recover_to_last_good_then_drop_again`). A held `next` line raises none of this.
- **The new check-entry type has its own name.** drift.go and preflight.go already name a type with the word the private-term scan refuses, so no added line may use it, and none of this plan's comments, tests, docs or messages uses the word. The new entries are `DrainingCA` values.
- **bundle_behind keeps `since` in its own small file.** `bundle-behind.json` (mode 0600, at most 4 KiB, strict canonical JSON `{"manifest_bundle_version":N,"since":"<time>"}`) is written by buildStatus, which runs under the apply lock on every apply and every check, when the accepted KRL manifest first names a bundle above the accepted one, kept while it does, replaced when a still newer version is named (the since time stays), and removed once the accepted bundle reaches the manifest's version. The status reports the field only once `now - since` reaches 2 hours (7200 s). The heartbeat's previous status cannot carry it, because the field is omitted during the grace. `keyroster-agent check` reads the record and never writes it. The reason is derived from persisted facts only: `unapplied` when the unapplied record's bundle version is at least the manifest's, else, when the spool is configured and lists the complete document set `bundle-<N>.json` and `bundle-<N>.json.sigs` for the manifest's version, `not_accepted` (this build verified it and did not accept it: a refused or held bundle, an older build refusing `draining` included), else `not_delivered`; `unknown` when no spool is configured (the check command) and nothing is recorded.
- **Heartbeat validation has no cross-field rule.** Validate requires the two versions to be at least 1, `since` in trust's timestamp format and a reason from the closed set; like the Unapplied precedent (heartbeat.go:422) it has no rule against the versions in force, so a status written while accepted/ moved never makes the server refuse a heartbeat.
- **The rotation vector has one more companion.** `test/vectors/user_ca_keys_rotation_v1.txt` is the expected `user_ca_keys` of the vector bundle, pinned by the repository's golden convention (TestGoldenVectors: built from the fixture, compared with the file, rewritten only with `-update`), so the agent's golden for the plain-line rule and the CLI plans' live count (03-12d) share one expected text.
- **The tracer is a Run-level test.** TestDrainingDropTracer starts keyroster-agent's Run loop on a hand-built draining bundle (the only way one reaches an agent: first acceptance of a hand-signed version of at least 2, which runs no chain rule) and moves the fake clock across trusted_until; the unit and Apply-level cases are expansion.
- **paths.go and its test are not edited, and the status `refusals` list is unchanged.** paths.Allowed already permits anything under the state directory (paths.go:146-171) and TestPaths (paths_test.go:150) scans the whole agent statically for writes without Allowed, which the latch's `e.writeState` satisfies; CheckStateDirs (enroll.go:270) checks directories only, so the latch's own mode and owner check is in its reader; `refusals` (status.go:354) lists refusals by design, and the latch adds none (an unreadable latch is a render rule, a failed write a tool error).
- **The doctor line keeps its shape.** doctor.go:303 prints `<state> g<N> <fingerprint>`; a draining generation reads `draining g<N> <fingerprint> until <t>`. The early plan's `draining g<N> until <t>` would move the fingerprint and break the pinned substrings of TestDoctorGenerations.
- **Mutant numbers.** The early plan's M135 to M148 keep their numbers (the design cites them, and no other plan or main file does); the mutants this reconcile adds are numbered after the highest used anywhere (M207, in 03-12b), from M208.
- **Test-time gate.** This plan edits tests in internal/agent/apply (about 650 s at a base measured at 09bd678) and cmd/keyroster-signer, so those two are in the gate; it changes nothing under cmd/keyroster, which is left out of the gate (its tests run in the whole-module run), so the cmd/keyroster margin of 03-12b (+63.9 s of 90) is not at risk.

## The output contract

These texts and names are fixed, byte for byte where tests match them.
- **Validate** (ErrInvalid, each text holds the entry's `cas[i] (role)` prefix as the existing ones do): `state "<s>" (want active, next, draining or retired)`; `a version 1 bundle has no draining entry`; `a draining entry needs a trusted_until` (an empty or unparsable one is the checkTimestamp error wrapped under `trusted_until:`); `trusted_until on a <state> entry (only a draining entry has one)`; `role <role> has more than one next entry`. `"trusted_until":""` is refused as non-canonical, as `"installation_id":""` is.
- **Summary** (internal/rootceremony): a draining entry's line gains `  trusted until <t>` at its end (two spaces, trust.TimeFormat), every other line is unchanged; the golden for the rotation vector is `testdata/summary/draining.golden`.
- **user_ca_keys:** one `trust.FormatKey` line plus a newline per trusted entry, user role then machine role, each by generation; no option, no comment, no blank line.
- **The latch** `<state>/trust-dropped.json`: strict canonical JSON `{"version":1,"keys":[{"fingerprint":"SHA256:...","trusted_until":"<time>"}]}` sorted by fingerprint, at most 64 KiB, mode 0600, the applier's uid.
- **bundle-behind.json** `<state>/bundle-behind.json`: `{"manifest_bundle_version":N,"since":"<time>"}`, at most 4 KiB, mode 0600.
- **The heartbeat field** `bundle_behind` (omitempty, after `unapplied`): `{"manifest_bundle_version":N,"accepted_version":M,"since":"<time>","reason":"<r>"}`, with `<r>` one of `unapplied`, `not_accepted`, `not_delivered` and `unknown`; `since` is the first time the accepted manifest named a newer bundle, and the field is present only once 2 hours (7200 s) have passed.
- **`keyroster-agent check`** (omitempty keys of the JSON report): `draining` lists every draining user and machine entry of the accepted bundle as `{role, generation, fingerprint, trusted_until, state, in_file, latched}` with `state` `draining` before the end and `drained (ended <trusted_until>)` from it; `trust_expired` lists the entries whose end has passed (or that the latch holds) and that current's `user_ca_keys` still holds; `trust_latch` is `unreadable` when the latch does not read; `bundle_behind` is the heartbeat object. Run's log line is `keyroster-agent run: ERROR trust_expired: <role> g<N> <fingerprint> ended <t> and is still in user_ca_keys; applying`.
- **doctor:** a draining generation prints `draining g<N> <fingerprint> until <trusted_until>`; other states print as before.
