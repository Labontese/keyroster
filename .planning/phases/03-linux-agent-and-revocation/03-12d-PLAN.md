<objective>
The CLI readers of the rotation (D-14, KEY-08): a client's known_hosts, a login, a machine renewal and the admin's convergence view use the same CA trust rule as the agents, so a rotation does not fail a login or a connection, a drained host CA does not stay in a client's file for ever, and the admin can see when it is safe to switch.

Purpose:
- **Narrowing everywhere.** Every command that verified a bundle removes the host CA lines the bundle no longer trusts, whatever happens to that command afterwards. This is the CLI's half of the drop that 03-12c gave the agents, and it is the path PR 108 needed three fix rounds for in the agent, so this plan enumerates every early return and error path of every such command and decides each one.
- **The issuing set.** A login and a machine renewal that span a switch are not refused (T-03-422), and a cached machine certificate of a draining CA is kept until it is due.
- **The gate.** `host status` shows, from what each host reports, how many hosts hold the new user CA keys, so ceremony 2 waits on a fact and not on a version number (T-03-76, T-03-416).

## Planner decisions (Claude's discretion), recorded with their reasons

- **One wrapper, called right after Trust, is the structural answer to the early-return bug class.** `verifiedTrust(ctx, client, cfg, stderr)` in cmd/keyroster/narrow.go calls `client.Trust` and then narrows with the bundle it returned. The early plan listed six callers and assumed one wrapper could serve them; main at 4184809 has 11 pinned callers in 8 files (dirpipe.go:129, host.go:331 and :362, hoststatus.go:121, knownhosts.go:1066, login.go:183, machinerenew.go:112, revoke.go:116, user.go:123, :395 and :649) and one unpinned one (init.go:135). Every call site has a client, a config and a stderr writer in scope except the admin session, which gains a `stderr` field. A static test (`TestTrustCallersUseWrapper`) parses every non-test .go file of the package directory with go/parser, whatever its build constraints, and fails on any selector named `Trust` or `TrustUnpinned`, called or not and with any number of arguments, outside `verifiedTrust` and `runInit` (so a method value or a wrapper of the wrapper is caught too), and a second leaf pins who may reference `narrowHostTrust`; a later command cannot forget the narrowing. The hook cannot be placed inside internal/serverclient: the narrowing needs the CLI's ~/.ssh and config paths, and the agent's fetcher links that package.
- **The narrowing is a filter on the file, not a rewrite from the bundle.** Rebuilding the file from the bundle (as the writer does) would need the active names, which only a verified directory gives, and could add a line. A filter is a subsequence of its input by construction, which is what "never adds a line" needs; the pure function `narrowKnownHosts(data, trusted)` has a fuzz target and a subset property test.
- **The line rule.** The file is split after each newline so every kept line keeps its own bytes (a CRLF, a missing final newline). A line whose first field equals `@cert-authority`, with the fields split on spaces and tabs (OpenSSH ends a marker at the first space or tab, hostfile.c check_markers) and leading blanks skipped, is a CA line. The marker is compared without regard to case: OpenSSH compares it with strcmp, so a case variant is a line OpenSSH refuses, and removing such a line when its key is not trusted is harmless, while a case-sensitive match here could only ever leave a line behind. A CA line is kept only when its third and fourth fields (`<type> <base64>`) are exactly the canonical text of a key in `TrustedCAs(b, host, now)`. A CA line with fewer than four fields, with a key that does not match, or with a key the bundle never named is removed (OQ-D). Every other line (comments, the informational version line, a plain host key, an `@revoked` line, a blank line) is kept untouched. The informational version line stays as the last full refresh wrote it; it is never read back.
- **The floor protects the lines in the file.** host-trust.json's `bundle_version` moves only when a refresh writes (the writer's `next.BundleVersion`), never when a command merely verifies a bundle. Every CA line in the file was written from a bundle at or below that floor, and entries are never removed from later bundles, so any bundle at or above the floor names every key in the file. Narrowing with such a bundle removes a line only when the bundle itself says the key is no longer trusted at the client's clock; an older bundle (a signer restore) does not name later keys and would remove a `next` line, which is why it narrows nothing. The state is read, never written.
- **Doubt narrows nothing, and says so, but only when there was something to narrow.** The order is: resolve ~/.ssh, examine the file (a file that is not regular, unreadable or larger than `maxNarrowFile`, 5 x maxHostTrustNames or 20 MiB, cannot be examined and warns at once), parse the trusted keys (one that does not parse warns, because a skipped key would narrow more), run the pure filter, and return silently when it would remove nothing. Only a filter that would remove a line goes on to the guards: a missing or damaged state, a state of another installation, an older bundle (the writer prints its own older-bundle warning at refresh, so a command that only verifies the bundle warns only when a narrowing was actually declined), an equal-version bundle with another ops key, the hook, the write that is checked, and a write that fails. Each prints one `Warning: host CA lines not narrowed in <path>: <reason>.` on stderr and changes nothing else, so a steady-state client never sees noise. A missing file is silent, and so is a ~/.ssh that cannot be resolved because there is no home directory (`errNoHomeDir`, which `defaultSSHDir` wraps and TestMain's error wraps, so every test of the package runs with the hook silent and no existing command test changes); a `$HOME` that is not the account's home (knownhosts.go:139) is not silent, because ssh reads the file from the account's home and the narrowing cannot reach it: it prints the warning with the error as the reason.
- **The write is checked, as the writer's D-R1 checks its own.** The write goes through `replaceManagedFile` with a `check` that runs right before the rename and refuses when the file on disk is no longer the bytes that were read, or when the state on disk is not the state that was read before the filter (any difference, which covers a newer bundle, directory or KRL version and another directory SHA-256, the quantities the writer's `newerHostTrustState` compares). That keeps the narrowing from putting back a name or a line that a concurrent refresh changed. A rename right after the check can still land behind a concurrent run, as in the writer (the runbook already states that residual); the next refresh rewrites every file.
- **stderr only, never the exit status.** The narrowing's message and warnings go to stderr, because stdout is consumed (`host ca-key > file`, `host principals > file`, `--json`), and a narrowing problem never fails the command that verified the bundle, the login (whose host trust outcome never changes its exit code) included.
- **`init` narrows after its unpinned Trust; the offline commands do not.** `init --force` re-runs against a saved installation and verifies a bundle against the root pins, so the owner's rule (every run that verified a bundle narrows) applies to it. `runInit` calls `TrustUnpinned` (the one call outside the wrapper) and then `narrowHostTrust` itself; the installation guard decides, so an `init` against another installation's bundle declines and a first `init` with no state and no file does nothing. `root`, `trust verify` and `audit verify` read files and never call Trust. Commands that fail before Trust (no config, no agent key) or whose Trust fails (network, pins, installation pin) have no verified bundle and narrow nothing.
- **Login set and text.** `issuingUserCAs(bundle)` parses `trust.IssuingCAs(bundle, user)`; an empty set keeps the error `the root-signed trust bundle has no active user CA`. `checkLoginCert` takes the set, accepts a signature key equal to any of them, and its CertChecker authority callback accepts the same set. The refusal text `it is not signed by the user CA of your root-signed trust bundle` is kept: TestLoginRefusals/`cert_other_ca_refused` pins its first words.
- **Machine renew.** `machineCAKeys` becomes `machineIssuingKeys` (the same active-or-next loop, now over `trust.IssuingCAs`) and the fresh answer keeps it; `machineCertCurrent` takes the set `machineTrustedKeys(b, now)` over `trust.TrustedCAs(b, machine, machineRenewTimeNow())`. TestMachineRenewChecksAnswer/`answer_by_draining_refused` already passes at 4184809 (a draining key is not active or next): it is a control that pins the boundary, with its own mutant.
- **`host ca-key` keeps its line.** Each trusted user CA prints as the existing `<key> keyroster user CA (bundle vN)`; the state, generation and end go to stderr and only when the set is not one active key. Five consumers pin the single line (role_test.go:357 and TestHostCAKey :374, test/e2e/roles_test.go:111-121, test/distro/world_test.go:168-171, host-setup.md:120-128 and :245-258); all stay green because a one-key set is byte-identical (OQ-C).
- **The live count.** The hash in `Status.Files` is the generation record's hash of the bytes the agent rendered, not a re-hash of the file on disk and not what sshd reads; the host's own report of a difference is its last drift check, so the count fails closed on that report. A row counts when it has a heartbeat, no swap pending, is not silent, status_stale or seq_regressed, has a `LastCheck` that carries no error and no drift, is not `stuck`, has a check that is not older than its last apply (`LastCheck.At` not before `LastApply.At` when both parse, because status.go carries the previous check across an apply and a clean check from before the apply must not vouch for the new generation), and lists `user_ca_keys` with the expected SHA-256. A host that has run no check yet (`LastCheck` nil) is not counted: a check follows every applying round (apply/run.go:79), so that wait is at most one round. `Effective.TrustedUserCAKeys` is left out on purpose: its path is the agent's, the CLI cannot know it without the linux-only package, and a difference in it is what the drift check already reports as drift. A host that would be counted by its hash but fails one of these rules gets a note with the reason, as the truncated status does. The expected file is `trust.UserCAKeysFile(bundle, now)` on the CLI's clock, the bundle being the one `Trust` verified. If that bundle is not the server's current one (version, or the SHA-256 of its canonical bytes) no host is counted and the line says why. A host whose status is truncated (`files_truncated`) and lacks the entry cannot be confirmed: apply/status.go:207-208 sorts a generation's files and keeps the first 256, and `user_ca_keys` sorts after `principals/*` and `revoked.krl`, so a host with 255 or more principals files never counts; it gets a note and the admin checks it with `keyroster-agent check`. The count is the server's word and the host's own report, as the footer says. The path `user_ca_keys` is a local constant because internal/agent/apply is linux-only; a linux-tagged test pins it to `apply.CAFile`.
- **Lenient decoding is a pinned fact.** serverclient's `send` decodes with `json.Unmarshal` (client.go:444), so an older CLI ignores the `bundle_behind` object of a newer status and only lacks the column; a test pins an unknown status field as ignored, so the decode never turns strict by accident.
- **Time.** `trustClock` (a `time.Now` variable, replaced in tests) is the client's clock for the host CA lines, `host ca-key`, `init` and `host status`; login and machine renew keep their own existing clocks (`loginNow`, `machineRenewTimeNow`). `renderHostsStatus` gains the verified bundle as a parameter and keeps its `now`, which `runHostStatus` fills with `trustClock()` (it passed `time.Now()`), so most `host status` cases are pure and the end-to-end case can put the clock and the wall clock on opposite sides of a draining end.
- **Tests and the test-time gate.** The guard matrix, the line rules and the status cases are pure functions or one htFix write; full CLI runs are limited to the tracer, one case per receiver shape of the wrapper, the login and renew paths and `host ca-key`. cmd/keyroster is the only package whose tests change, so it is the gate (Budget).
- **Mutant numbers and threat IDs.** M149 to M154 keep the numbers the early plan reserved and the design cites (no other plan or main file uses them); the mutants this reconcile adds are numbered after the highest used anywhere (M232, in 03-12c), from M233 to M279. T-03-444 to T-03-448 are free in every plan file and on main (T-03-449 occurs only in a SUMMARY sentence and is skipped).

## The output contract

These texts and names are fixed, byte for byte where tests match them.
- **Narrowing, stderr, one line:** `Host trust narrowed: removed <N> CA line(s) of host CAs the trust bundle no longer trusts from <path>.`
- **Narrowing warning, stderr, one line:** `Warning: host CA lines not narrowed in <path>: <reason>.` with `<reason>` one of: `the host trust state is missing`; `the host trust state is damaged (<error>)`; `the host trust state belongs to installation <a>, not to <b>`; `the server serves trust bundle version <n>, older than version <m>, which this client verified before`; `trust bundle version <n> names another ops key than the version this client verified before`; `it cannot be read: <error>`; `it is not a regular file`; `it is larger than <max> bytes`; `a trusted CA key of the bundle does not parse`; `the file changed while it was read`; `another run recorded a newer host trust state meanwhile`; `writing it failed: <error>`; and, for a `$HOME` that is not the account's home, the error that `defaultSSHDir` returns (knownhosts.go:139), with `<path>` then read as `~/.ssh/keyroster_known_hosts`. `<path>` is the managed file's path. The warnings for a file that cannot be examined (`it cannot be read`, `it is not a regular file`, `it is larger than`), for a trusted key that does not parse and for the `$HOME` mismatch print whenever a command verified a bundle and there is a file or a home to examine; every other reason prints only when the line filter would have removed at least one line. Nothing else is printed, and nothing is printed when there is no home directory to resolve, when the file is absent, or when the file holds nothing to remove.
- **`host ca-key`:** stdout is one line per entry of `trust.TrustedCAs(b, user, now)`, in generation order, each `<key> keyroster user CA (bundle v<N>)` and a newline, and nothing else. When that set is not exactly one active entry, stderr gets, after the custody banner if any, the line `keyroster host ca-key: the trust bundle trusts <n> user CA keys; a host that keyroster-agent does not manage needs every line of the output.` and one line per entry `  generation <g> <SHA256:fingerprint> <state text>`.
- **State text** (`caStateText`, used by `init`, `host ca-key` and `host status`): `active`, `next` and `retired` as the bundle says; `draining, trusted until <t>` while the entry's end is in the future; `drained (ended <t>)` from the end on. `<t>` is the bundle's `trusted_until`, trust.TimeFormat.
- **`init`:** each CA line reads `<role> CA <fingerprint> (custody <c>, <state text>)`.
- **`host status` header:** after the three existing lines, `user CA keys of bundle v<N> live on <X>/<M> hosts`, or, when the verified bundle is not the server's current one, `user CA keys not counted: the trust bundle this client verified (v<a>) is not the server's current one (v<b>)`; then one line per draining entry of the verified bundle, in bundle order: `<role> CA generation <g> <SHA256:fingerprint>: draining, trusted until <t>` or `<role> CA generation <g> <SHA256:fingerprint>: drained (ended <t>)`.
- **`host status` table:** the columns are `HOST`, `DIRECTORY ENTRY`, `LAST SEEN`, `STATUS`, `BUNDLE`, `DIRECTORY`, `KRL`, `GENERATION`, `AGENT`, `DRIFT`, `LAST APPLY`, `BEHIND`, `ALERTS`. AGENT is the heartbeat's `agent_version` or `-`; BEHIND is `-` or `v<manifest version> for <age> (<reason>)` from `bundle_behind`, every cell passed through `safe`. A host whose status is truncated and lacks `user_ca_keys` gets the note `<host>: user CA keys not confirmable: its status lists only the first 256 files (files_truncated); run keyroster-agent check as root on the host`. A host whose file hash matches but whose own report fails a rule gets `<host>: user CA keys not confirmed: <reason>; run keyroster-agent check as root on the host`, with `<reason>` one of `its last check reported drift`, `its last check failed`, `it is stuck`, `it has not run a drift check yet` and `its last check is older than its last apply`; such a host is not counted.
- **The wrapper's contract:** `verifiedTrust` returns exactly what `client.Trust` returns, makes no request of its own and prints nothing on stdout.
