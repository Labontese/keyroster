## The output contract

- **The ceremony:** `--ca-switch ROLE` (repeatable, needs `--prev`), `--drain-allowance DURATION` (default 24h, whole seconds, from 0 to `trust.MaxDrainAllowance`, needs `--ca-switch`, which is read with `fset.Visit` because the default is 24h and a value check cannot tell; usage text `root sign: --drain-allowance <d> is above the cap of 168h0m0s`). ## Lessons from PR 108, PR 109, PR 110, 03-12, 03-12b, 03-12d and 03-12e, and where this plan applies them

- **A count or gate another step relies on depends on what its publisher writes (PR 109).** The live count, `keyroster-agent check` and the heartbeat's user_ca_keys hash are named with their publisher in the runbook and the e2e; a remedy names the command that changes the state it reads (a manual `keyroster-agent check` writes no status; `keyroster-agent apply --once --recover-to-last-good` does).
- **Fail-closed paths (the inverse of PR 108's narrowing lesson).** The tool's own refusals (a flag without its partner, an allowance outside the cap, a role without a `next`) are in the tool's table with a case and a mutant; the signer's and audit's are 03-12e's.
- Every `grep -x` over text with brackets or metacharacters is `grep -Fqx`; every `-run` pattern uses `^(A|B)$` and separate subtest patterns; every verify that scans added lines scans only added lines of a `-U0` diff and asserts the diff is not empty.
- The executor runs `git diff --cached` on every staged file and reads all of it before each commit and amend; the SUMMARY records it per commit. 03-12e's SUMMARY records three staged diffs read as the executor had written them instead of from the diff (its deviation 21, which the owner had to rule on): the read is of `git diff --cached`, in parts if long, and never of one's own edit text.
- A root-run shell in a runbook, a smoke or an e2e text creates, changes, redirects into or removes nothing below a directory a less-privileged account owns: the ceremony-2 install block runs every write through `runuser`, both checks run, and an added-line scan reads the new text.
- golangci-lint runs locally before the first push and after each T commit; the portable packages are vetted for windows and darwin; a parameter that is not used yet is named `_`; the PR branch name is defined once.
- The test-time delta gate covers cmd/keyroster with its base re-measured in the executing session; the e2e lane's time is budgeted and has an owner stop rule.
- Mutants keep every variable referenced, so a kill is an assertion and never a build failure.
- The pre-merge review is not skipped by default: Task 5 does not start until it is recorded or the owner says to skip it, and the SUMMARY records what happened.
- **A runbook block that writes under the signer's directory removes the old file first and chains the steps (PR #110, review fix 1, medium).** signer-install.md's switch block copied `previous.jsonl` under `set -C` without removing an earlier switch's export and without chaining, so a second switch installed against a stale export, and a rollback or fork of the database between the two went undetected. Here both install blocks of ca-rotation.md, ceremony 1's (which W2 rewrites from a `for` loop) and the switch's, remove the files they copy as the signer's user, copy each file under `umask 077` and `set -C` through `runuser`, and chain the removal, the copies and the install with `&&`, one explicit line each, because a `for` loop cannot be gated per file. TestCARotationInstallBlocks pins the order and the chain of both (M331, M332) and T-03-458 records the threat.
- **Every `keyroster audit verify --pin` line of a runbook pins both roots (PR #110, review fix 2, medium).** `trust.MatchPins` needs the pinned set to equal the bundle's root set, so one pin fails a valid export and sends the operator to escalate as for a fork. TestRunbookAuditVerifyPins enforces two pins per line in every runbook, but it sees only lines that carry `keyroster audit verify --pin SHA256:`; this plan writes its commands in that form and adds the leaf `audit_verify_pins_both_roots`, which joins continuations and so also covers the existing ceremony-1 command (M333, T-03-459).
- **A split's sibling plan is placed in the working tree at dispatch (PR #110, Merge addendum).** 03-12e's Task 9 stopped because this plan was not in the working tree. Here the placement is Task 1's first precondition (the file's sha256 against the dispatch's, main's copy against its known hash), and the SUMMARY records the hash that P4 and its checks read.
- **CI lints three platforms, so a gate that lints one lets a failure through (PR #110, deviation 32 and the lint fix of its review).** The local golangci-lint run is repeated under `GOOS=windows` and `GOOS=darwin` after each R and T commit and in the full gate, and conditions in new tests are written in the reduced form QF1001 wants.
- **A free-ID check reads definition rows, not mentions (found at this reconcile).** The check of M286 to M289, M319 and M320 failed at 034b1d9 because 03-12e's plan, now on main, names them in prose; Task 1 reads table rows only, and the ledger records that nothing needed renumbering.
- **A record of a CI run cannot name the run of its own commit (PR #110, deviation 29).** The SUMMARY names the runs that exist when it is written; the pre-merge review's docs commit adds the IDs of the head it reviewed.
- **A gate that searches for a word fails when the line it must change holds the word (plan check of this text).** The e2e.yml `-run` list shares a line with `-timeout 20m`, so a check that refused any changed line holding `timeout` could never pass; compare values, and normalise the lines that are allowed to change.
- **A helper that Fatalfs, or issues a fixed TTL, must be checked against the profile the test sets (plan check).** `issueAgentCert` (10m) and `enrollApproved` (a 1h role) fail under a 60 s user profile, and a goroutine that calls a Fatalf helper loses its counts; the loop uses `os/exec` helpers that return errors and the test asserts attempts and gaps, so a loop that stopped cannot pass.
- **An RED leaf that runs in its parent's body cannot fail on its own (plan check).** The golden case runs its commands in its body, so on R1 only the case fails; a RED list names the lines that really print.
