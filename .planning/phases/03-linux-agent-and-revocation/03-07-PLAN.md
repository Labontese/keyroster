**Applier side.** `keyroster-agent install --join-file FILE [--root /] [--state-dir /var/lib/keyroster-agent]`:
- parse the join string, and refuse when the system user `keyroster-agent` does not exist (the runbook creates it);
- create every path of the F2 install truth (addresses review concern F2, REVIEWS L1362, L1417@e7b3b32), each with its owner and mode, relative to an O_NOFOLLOW descriptor of its parent (spool.OpenDir), with files through spool.WriteFileAt: `<state>`, accepted/, pins.json, `<root>/etc/keyroster-agent/fetch.json` {server, tls_roots, tls_pins}, `<root>/var/lib/keyroster-agent-fetch/join-token`, the spool `<state>/spool` and the outbox `<state>/outbox`;
- refuse `install_path_unsafe` for a pre-existing path that is a symlink, of the wrong type, or has another owner or a wider mode;
- extend paths.Allowed with exactly these.

`keyroster-agent run [flags of apply]` is a loop every 5 s. At the start of each round it runs 03-05's `state_dir_unsafe` check, extended to the outbox. Then it:
- (a) answers an `enroll-request.json` in the spool:
  - read through spool.ReadFileAt with a 4 KiB cap;
  - fields: identity_spki_sha256 and token_sha256 as 64 lowercase hex, expected_name by the directory host-name grammar, and installation_id equal to pins.json, else `enroll_request_invalid`;
  - read the host private keys named by the `sshd -T` hostkey lines (refusing `host_key_unreadable` for agent-held keys), sign the PoP with the installation ID from pins.json, and write `enroll-pop.json` into the outbox with spool.WriteFileAt;
- (b) runs Apply when the spool holds anything newer. Config.AllowAdoption stays false here (03-06: adoption is a hand-run `apply --once`).

The `keyroster-agent identity` command is not on the tracer's path; Task 2 adds it. It reads identity.pub through spool.ReadFileAt.

**Fetcher (cmd/keyroster-agent-fetch, internal/agent/fetch).** Runs as keyroster-agent; flags `--config /etc/keyroster-agent/fetch.json --dir /var/lib/keyroster-agent-fetch --spool ... --outbox ... [--poll 60s]` (minimum 1 s for tests; default 60 s with ±10 s jitter from crypto/rand). On first start generate the Ed25519 identity (0600) and a self-signed certificate (CN keyroster-agent, serial random, NotBefore now−1 h, NotAfter +100 y; the server ignores validity and pins the SPKI) and write identity.pub to the spool. While a join-token file exists:
- write `enroll-request.json` {identity_spki_sha256, token_sha256, expected_name, installation_id};
- wait for `enroll-pop.json` in the outbox, read through spool.ReadFileAt. If its PoP names another identity or token hash, it is not posted (`enroll_pop_mismatch`, logged; the fetcher waits for a fresh one);
- POST /api/v1/agent/enroll {token, host_keys, sigs, facts}; on 202 delete the token file.

Then poll GET /api/v1/agent/state with the versions of the newest spool files:
- 403 `not_approved` waits;
- 200 writes every item with spool.Write. The names are built from the item's kind and its uint64 version; the response carries no file names;
- the body is read through serverclient/agent.go's own limit, `MaxAgentStateResponse = 8 << 20`, and refused `state_response_too_large` above it before JSON decoding. client.go's 4 MiB `maxResponse` stays for the other calls; a maximum KRL in base64 does not fit it (F12, REVIEWS L1372@e7b3b32);
- while the response says `more: true`, request again at once with the new versions, at most 64 times per poll.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| join string (secret) → host | Whoever holds it can enroll one pending host until it expires |
| fetcher (network, unprivileged) → applier (root) | The fetcher may be compromised; it can only withhold or delay |
