<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Workflow → GITHUB_TOKEN | Every workflow run receives a token; its default scope decides blast radius |
| Third-party actions → runner | Actions run with the job's token and source checkout |
| Reporters → maintainers | Vulnerability details must not cross into public view |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-18 | Elevation of privilege | GITHUB_TOKEN defaults | high | mitigate | `default_workflow_permissions=read`, `can_approve_pull_request_reviews=false`, `permissions: {}` in every workflow |
| T-01-19 | Tampering | Third-party actions | high | mitigate | Selected-actions allowlist (GitHub-owned + two named actions), `sha_pinning_required`, `pinned-actions` check |
| T-01-20 | Information disclosure | Committed secrets | high | mitigate | Secret scanning with push protection enabled and verified via API |
| T-01-21 | Information disclosure | Vulnerability reports | medium | mitigate | Private vulnerability reporting enabled; issue config routes reports there; SECURITY.md forbids public issues |
| T-01-22 | Tampering | Vulnerable dependencies | medium | mitigate | Dependabot alerts + security updates, CodeQL security-extended, govulncheck (01-01) |
| T-01-SC | Tampering | codeql-action, scorecard-action | high | mitigate | Official GitHub and OpenSSF actions, SHA-pinned; no package-manager installs in this plan |
