Prove against real sshd that the user, host and machine CAs from 01-07 are separate and never interchangeable, and anchor `keyroster audit verify` on the operator's pinned roots instead of a bare log key.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Export → audit verifier | The verifier anchors on pinned roots, not on anything in the export |
| Host CA → ssh clients | Clients trust host certificates through an @cert-authority line instead of TOFU |
| CA roles → sshd | sshd must reject certificates from the wrong CA or of the wrong type |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-40 | Spoofing | `audit verify` anchors | high | mitigate | Pins only from `--pin`; bundle_install leaves verified against them before the log key or CA keys are trusted; tamper tests for unpinned roots, threshold and log-key change |
| T-01-72 | Elevation of privilege | CA role confusion at sshd | high | mitigate | e2e on 9.5p1 and 10.5p1: machine-CA and host-type certificates rejected where only the user CA is trusted; host certificates accepted only through the host CA's @cert-authority line, and an empty known_hosts fails instead of falling back to TOFU |
| T-01-SC | Tampering | dependencies | low | accept | No new modules or packages in this plan |
</threat_model>
