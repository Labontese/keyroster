**internal/directory/render.go.** `AccountPrincipals(d *Directory, hostGroup, account string) ([]string, error)` returns the sorted, de-duplicated union of the principals of the roles mapped to that account. It errors when the host group or the account is unknown. `RenderPrincipalsFile(d *Directory, hostGroup, account string) ([]byte, error)` emits:
- `# keyroster: generated AuthorizedPrincipalsFile; do not edit`;
- `# host group <g>, account <a>, directory version <n> sha256 <hex>`;
- one principal per line, with a trailing newline.

sshd ignores `#` lines in principals files.

**CLI** (each mutating subcommand is an editDirectory mutation and accepts `--yes`, `--out DIR` and `--admin-key`):
- `keyroster role add NAME --max-ttl DURATION [--principal P]... [--extension E]... [--user U]... [--group G]...`. Without --principal it grants the Task 1 default (`role:NAME` for role-prefix). --max-ttl takes Go duration syntax, rounded to seconds, minimum 1 minute.
- `role update NAME [--max-ttl D] [--principal P]... [--extension E]...`: given lists replace the old ones.
- `role remove NAME`. It refuses while a host group maps the role, and names the host groups.
- `role grant NAME --user U|--group G` and `role revoke ...`.
- `keyroster group add NAME [--member U]...`, `group remove NAME` (refused while a role grants it), `group add-member NAME U...` and `group remove-member NAME U...`.
- `keyroster host-group add NAME`, `host-group remove NAME`, `host-group map NAME ACCOUNT ROLE...` (sets the account's role list) and `host-group unmap NAME ACCOUNT`.
- `keyroster host principals GROUP ACCOUNT`: Trust, then fetch the directory and verify it locally (the same steps as the pipeline, read only), then print RenderPrincipalsFile to stdout.
- `keyroster host ca-key`: Trust, then print the active user CA entry from the verified bundle as an authorized-keys line with comment `keyroster user CA (bundle vN)`.

Before signing, every principal is checked with cert.ValidatePrincipals, and the directory with Validate and CheckPolicy through the pipeline. Error messages name the offending role.
