**internal/directory/render.go.** `AccountPrincipals(d *Directory, hostGroup, account string) ([]string, error)` returns the sorted, de-duplicated union of the principals of the roles mapped to that account. Empty-mapping semantics, one rule (addresses review finding 02-11-F2):
- an unknown host group is an error (`ErrUnknownHostGroup`), which catches a mistyped group name;
- in a known host group, an account with no entry, or an entry whose role list is empty, returns an empty, non-nil list and no error. 02-01's Validate accepts an AccountMap with `roles: []`, so the renderer must treat that exactly like an absent account. An unmapped account is a valid state that grants nothing, not an error, so a caller can never be tempted to keep the previous file;
- a nil `*Directory` returns the new sentinel `ErrNoDirectory` from both functions, and neither dereferences it. No directory is installed until the first admin-signed version (02-09's `fetchVerifiedDirectory` then returns `Version == 0` with a nil `Dir`), and in that state there is no host group to render for.

`RenderPrincipalsFile(d *Directory, hostGroup, account string) ([]byte, error)` emits:
- `# keyroster: generated AuthorizedPrincipalsFile; do not edit`;
- `# host group <g>, account <a>, directory version <n> sha256 <hex>`. `<hex>` is the lowercase hex SHA-256 of `d.Canonical()`: the same value `keyroster directory show` and the signer's Status report, and the next version's prev. Parse is strict and Canonical is the one canonical rule, so for an installed directory it equals the SHA-256 of the stored bytes (addresses review finding 02-11-F5);
- one principal per line, with a trailing newline. With no principals the file is just the two header lines, and sshd accepts no keyroster certificate for that account.

sshd ignores `#` lines in principals files.

**CLI** (each mutating subcommand is an editDirectory mutation and accepts `--yes`, `--out DIR` and `--admin-key`):
- `keyroster role add NAME --max-ttl DURATION [--principal P]... [--extension E]... [--user U]... [--group G]...`. Without --principal it grants the Task 1 default (`role:NAME` for role-prefix). --max-ttl takes Go duration syntax, rounded to seconds, minimum 1 minute.
- `role update NAME [--max-ttl D] [--principal P]... [--extension E]... [--no-extensions]` (addresses review finding 02-11-F3):
  - a list flag that is given replaces the old list, and an omitted list flag keeps it;
  - `--no-extensions` empties the role's extra extension list, and is refused together with `--extension`;
  - principals cannot be cleared, because Validate requires 1-32 per role.
- `role remove NAME`. It refuses while a host group maps the role, and names the host groups.
- `role grant NAME --user U|--group G` and `role revoke ...`.
- `keyroster group add NAME [--member U]...`, `group remove NAME` (refused while a role grants it; the error names every granting role, addresses review finding 02-11-F6), `group add-member NAME U...` and `group remove-member NAME U...`.
- `keyroster host-group add NAME`, `host-group remove NAME`, `host-group map NAME ACCOUNT ROLE...` and `host-group unmap NAME ACCOUNT` (02-11-F2):
  - `map` sets the account's role list and requires at least one ROLE. With none it refuses with "give at least one role; to revoke the account's access use host-group unmap";
  - `unmap` removes the account's entry from the host group. Unmapping an account that has no entry is refused, naming the account.
- `keyroster host principals GROUP ACCOUNT [--admin-key SHA256:...]`: calls 02-09's `fetchVerifiedDirectory` (Trust, fetch, Parse, VerifySignatures against the quorum; read only), then prints RenderPrincipalsFile to stdout. The directory endpoint is admin-signed, so the admin key resolves as in the pipeline: `--admin-key`, otherwise config.AdminKey, otherwise a refusal with instructions. It never re-implements that glue (addresses review finding 02-11-F7). An unmapped account prints the header-only file and exits 0; an unknown host group exits non-zero. When no directory is installed, the command refuses before rendering. 02-09 pins the helper's contract: with a nil error its result is never nil and `Policy` is always set, and "nothing installed" is exactly `Version == 0` with a nil `Dir`, which is not an error from the helper. So `host principals` has one check, `Version == 0`, and maps it to its own error: it prints nothing to stdout and exits non-zero with "no directory is installed on the server; nothing to render" (wrapping `directory.ErrNoDirectory`). It carries no second check for a nil result. It never prints a header-only file in that state, because a header-only file means "this directory version grants the account nothing".
- `keyroster host ca-key`: Trust, then print the active user CA entry from the verified bundle as an authorized-keys line with comment `keyroster user CA (bundle vN)`.

Before signing, every principal is checked with cert.ValidatePrincipals, and the directory with Validate and CheckPolicy through the pipeline. Error messages name the offending role.
