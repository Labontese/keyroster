**Binary.** cmd/keyroster-server: main.go (`//go:build linux`) dispatches `serve`; main_other.go exits 1 with "keyroster-server runs on Linux only (PLAT-05)". The serve.go flags are `--listen` (default `:443`), `--tls-cert`, `--tls-key` (both required) and `--signer-socket` (default `/run/keyroster-signer/signer.sock`). Start-up runs in this order:
1. Call signerclient.Status, retrying for up to 30 s, then exit non-zero.
2. trust.ParsePolicy on Status.Policy. Exit non-zero with "the installed policy has no WebAuthn RP; add it with keyroster root successor-policy (docs/runbooks/root-ceremony.md)" when WebAuthn is nil.
3. Load the certificate holder (Task 2 adds reload). The leaf must pass `VerifyHostname(rp_id)` and be within NotBefore/NotAfter.
4. Listen with `tls.Config{MinVersion: tls.VersionTLS13, GetCertificate: holder.GetCertificate}`.
5. Serve with ReadHeaderTimeout 10 s, ReadTimeout 30 s, WriteTimeout 30 s, IdleTimeout 120 s and MaxHeaderBytes 16 KiB.
6. Log through slog JSON to stderr.

**internal/server.**
- `Config{SignerSocket string; Clock func() time.Time; Logger *slog.Logger}`, `New(Config) (*Server, error)` and `(*Server).Handler() http.Handler`. Routes use ServeMux method patterns: `GET /{$}` (index), `GET /static/` (embed FS, explicit content types), `GET /api/v1/trust` and `GET /healthz`.
- headers.go `secure(h)`: set every header in the must-haves on every response, including errors and static files, and wrap the handler with `http.NewCrossOriginProtection().Handler`.
- signer.go: a status cache (TTL 5 s, refreshed under a mutex) holding the parsed policy, the RP and the custody list. A Status failure serves 503 from the API and the healthz route, and an error page from HTML routes. Never fall back to stale RP data older than 60 s.

**internal/serverclient.**
- `New(Config{Server string; RootsPEM []string; Pins []string; Stderr io.Writer}) (*Client, error)`. It builds an http.Client whose transport sets `TLSClientConfig{MinVersion: TLS13, RootCAs: pool of the stored roots only, ServerName: host, VerifyConnection: require a verified chain whose root SPKI SHA-256 pin is in Pins}` and `Proxy: nil`, with a 30 s timeout.
- `(*Client).GetJSON(ctx, path, out)` and `PostJSON(ctx, path, in, out)`. Every response passes through `checkCustody`, which parses Keyroster-Custody and prints the banner once per Client.
- `(*Client).Trust(ctx, rootPins []string, threshold int) (*trust.Bundle, *trust.Policy, error)` fetches /api/v1/trust and runs `trust.VerifySelfSigned` then `trust.MatchPins`.
- `PinOf(cert *x509.Certificate) string` returns `sha256/` + base64 std of SHA-256(RawSubjectPublicKeyInfo).

**CLI.**
- cmd/keyroster/config.go defines `Config{Server string; TLSRootsPEM []string; TLSPins []string; TrustPins []string; TrustThreshold int; User string; AdminKey string}` as JSON at `os.UserConfigDir()/keyroster/config.json`, written 0600 in a 0700 directory, with `loadConfig()` and `saveConfig(c, force bool)`.
- cmd/keyroster/init.go `keyroster init`:
  1. Validate --server: https, host a DNS name (net.ParseIP nil after stripping brackets), optional port, no path, query or fragment.
  2. Build the pool from --tls-root-file (PEM, at least one CA cert) or from x509.SystemCertPool.
  3. `tls.Dial` with ServerName and that pool. Collect the root (last element) of every VerifiedChain and print each root's subject and PinOf.
  4. Require at least one --tls-pin and that every given pin was observed. Without --tls-pin, print the observed pins and exit 2 with "compare these with your invite and re-run with --tls-pin".
  5. Keep only the observed roots whose pins were given.
  6. Through serverclient with those roots, call Trust(--root-pin, --threshold). Print the bundle version, the root fingerprints, the user CA fingerprint and the custody.
  7. saveConfig. It refuses an existing file without --force.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser / CLI → keyroster-server (HTTPS) | Untrusted network; the CLI leg is protected by pinned roots, the browser leg by WebPKI |
| keyroster-server → signer socket | The server is untrusted by design; it can only forward payloads the signer verifies |
| operator files → server TLS identity | Certificate files rotate every ~60 days with a new key |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-25 | Spoofing | CLI to server TLS | high | mitigate | Root-CA pin set confirmed out of band at init; after init only pinned roots; VerifyConnection requires a pinned root; trust bundle verified against root pins |
| T-02-26 | Tampering | XSS / content injection in the UI | high | mitigate | html/template auto-escaping, no inline script or style, CSP default-src 'none' with self-only sources, nosniff |
| T-02-27 | Spoofing | clickjacking of approval or registration pages | medium | mitigate | frame-ancestors 'none', COOP same-origin |
| T-02-28 | Spoofing | server config moving the RP | high | mitigate | RP read only from the signer's root-signed policy; start refused without it; certificate must cover rp_id |
| T-02-29 | Denial of service | certificate renewal | medium | mitigate | Validated reload with last-good fallback, SIGHUP, renewal timer, 14-day warning |
