**Binary.** cmd/keyroster-server: main.go (`//go:build linux`) dispatches `serve`; main_other.go (`//go:build !linux`) exits 1 with "keyroster-server runs on Linux only (PLAT-05)". Every file in cmd/keyroster-server other than main_other.go carries `//go:build linux`, and main_other.go imports only `fmt` and `os`, as cmd/keyroster-signer/main_other.go does. On windows and darwin the package then depends on the standard library only, which keeps 02-01's `scripts/testonly-firewall.sh` (`go list -deps ./cmd/...` for linux, windows and darwin, with and without `-tags piv`, in the required dependency-firewall job) green. The serve.go flags are `--listen` (default `:443`), `--tls-cert`, `--tls-key` (both required) and `--signer-socket` (default `/run/keyroster-signer/signer.sock`). Start-up runs in this order:
1. Call signerclient.Status, retrying for up to 30 s, then exit non-zero.
2. trust.ParsePolicy on Status.Policy. Exit non-zero with "the installed policy has no WebAuthn RP; add it with keyroster root successor-policy (docs/runbooks/root-ceremony.md)" when WebAuthn is nil.
3. Load the certificate holder (Task 2 adds reload). The leaf must pass `VerifyHostname(rp_id)` and be within NotBefore/NotAfter.
4. Listen with `tls.Config{MinVersion: tls.VersionTLS13, GetCertificate: holder.GetCertificate}`.
5. Serve with ReadHeaderTimeout 10 s, ReadTimeout 30 s, WriteTimeout 30 s, IdleTimeout 120 s and MaxHeaderBytes 16 KiB.
6. Log through slog JSON to stderr.

**internal/server.**
- `Config{SignerSocket string; Clock func() time.Time; Logger *slog.Logger}`, `New(Config) (*Server, error)` and `(*Server).Handler() http.Handler`. Routes use ServeMux method patterns: `GET /{$}` (index), `GET /static/` (embed FS), `GET /api/v1/trust` and `GET /healthz`.
- Static content types (addresses review finding 02-06-F15): a map `staticTypes` gives `.css` → `text/css; charset=utf-8` and `.js` → `text/javascript; charset=utf-8`. The static handler sets that Content-Type explicitly and answers 404 for a file whose extension has no entry, so nothing is served with a sniffed type.
- headers.go `secure(h)`: set every header in the must-haves on every response, including errors and static files, and wrap the handler with `http.NewCrossOriginProtection().Handler`.
- signer.go, the signer seam (cross-plan audit). `type signerAPI interface { Status(ctx context.Context) (*wire.StatusResponse, error) }` is the only way from a handler in internal/server to the signer. The start-up probe in serve.go (step 1 above) runs before the Server exists and calls signerclient.Status directly; it is the one call outside the seam.
  - Production: `socketSigner{socket string}`, whose methods call the package-level signerclient functions with that socket. The Server keeps it in the field `signer signerAPI`, and handlers call `s.signer.<Method>`. signer.go is the only file in internal/server that imports the signerclient package.
  - Construction: the unexported `newServer(cfg Config, sg signerAPI) (*Server, error)` builds the Server. `New` calls it with `socketSigner{cfg.SignerSocket}`, and tests call it with `fakeSigner` (Task 2). There is no exported way to swap the signer.
  - Growth rule. A later plan that needs another signer call adds that method to signerAPI, to socketSigner and to fakeSigner in the commit that adds its first caller: `GetDirectory` in 02-07, `InstallDirectory` in 02-09, `Login` in 02-12. Nobody adds a second interface, and no method is added before something calls it (the no-unexercised-paths rule).
- signer.go, the status cache: it holds the parsed policy, the RP and the custody list, filled from `s.signer.Status`. Every handler that needs RP, custody, policy or directory state gets it only through `(*Server).currentStatus(ctx) (*statusView, error)`. Later plans (02-07 to 02-12) use the same accessor. One fail-closed rule (addresses review finding 02-06-F4; it replaces an earlier "no stale RP data older than 60 s" clause that implied a grace window):
  - an entry younger than 5 s (by Config.Clock) is returned from the cache;
  - otherwise the caller refreshes it under the mutex, with a 3 s timeout. The mutex is held for the whole signer call, and concurrent callers wait for that one refresh;
  - if the refresh fails, currentStatus returns the error and drops the expired entry. A failed refresh is never cached as a success, and the next request tries again;
  - on that error, API routes and /healthz answer 503 `{"error":"signer unavailable"}`, and HTML routes render error.html with status 503. Neither carries RP, policy, custody or directory data, nor a Keyroster-Custody header, because custody is unknown. serverclient reports such a 503 as "the server cannot reach its signer" and does not parse custody from it.
- signer.go, the invalidation hook (cross-plan audit, BLOCKER): `(*Server).dropStatus()` takes that same mutex and removes the cached entry. It makes no signer call and cannot fail.
  - The next currentStatus must therefore refresh, and it still fails closed when that refresh fails. Dropping never widens what is served.
  - Because the drop waits for a refresh that is in flight, an answer read from the signer before a change can never be put back after the drop.
  - Who calls it: a handler, right after the server asked the signer to change something Status reports. In phase 2 that is only the directory install (02-09). A bundle or policy install is `keyroster-signer install-bundle` with the signer stopped, which no server route performs, and issuing a certificate changes no Status field.
  - No handler in this plan calls it. Task 2's tests call it directly, so it is tested here and gets its first production caller in 02-09.
  - Without the hook, an edit made within 5 s of an install would be built on the old directory SHA-256 and refused by the signer.
- render.go: parse templates once from the embedded FS. base.html renders the custody banner block when `custodytext.SoftwareRoles` is non-empty: a `<div class="kr-banner" role="alert">` with the exact `SoftwareCABanner` text. Set `Keyroster-Custody: user=<c>, host=<c>, machine=<c>, ops=<c>, log=<c>` on every response built from a current status.
- `GET /api/v1/trust` returns JSON with `bundle`, `bundle_sigs`, `policy`, `policy_sigs` (base64 std), `bundle_version`, `directory_version` and `custody` (a list of {role, alg, custody, fingerprint}).
- web/: embed.go (`//go:embed templates static`); base.html (lang="en", no inline script or style, stylesheet `/static/app.css`); index.html (instance name = rp_id, policy and directory versions); error.html; app.css (plain CSS).

**internal/serverclient.**
- `New(Config{Server string; RootsPEM []string; Pins []string; Stderr io.Writer}) (*Client, error)`. It builds an http.Client whose transport sets `TLSClientConfig{MinVersion: TLS13, RootCAs: pool of the stored roots only, ServerName: host, VerifyConnection: require a verified chain whose root SPKI SHA-256 pin is in Pins}` and `Proxy: nil`, with a 30 s timeout.
- `(*Client).GetJSON(ctx, path, out)` and `PostJSON(ctx, path, in, out)`. Every response passes through `checkCustody`, which parses Keyroster-Custody and prints the banner once per Client.
- `(*Client).Trust(ctx, rootPins []string, threshold int) (*trust.Bundle, *trust.Policy, error)` fetches /api/v1/trust and runs `trust.VerifySelfSigned` then `trust.MatchPins`.
  - Rotated trust roots (cross-plan request 02-09-F11, from the 02-09 planner): a `trust.MatchPins` failure, after VerifySelfSigned has passed, is wrapped as `serverclient.ErrTrustRootNotPinned`.
  - Its message: "the server's trust bundle is signed by roots that do not match the --root-pin set you gave keyroster init. If the roots were rotated (docs/runbooks/root-ceremony.md \"Rotate the roots\"), get the new root fingerprints and threshold out of band from the root holders' records, never from the server, and run `keyroster init --force --server <URL> --tls-pin <pin> --root-pin <new fp> [--root-pin …] --threshold <n>`".
  - The message never contains the served bundle's root fingerprints, so a hostile server cannot hand the user the pins to type.
  - A VerifySelfSigned failure (a bundle that does not verify under its own roots) keeps its own error and gets no re-init hint.
- `PinOf(cert *x509.Certificate) string` returns `sha256/` + base64 std of SHA-256(RawSubjectPublicKeyInfo).
- Pinned-root mismatch (addresses review finding 02-06-F10). Because RootCAs holds only the pinned roots, a server whose CA moved to a new root fails in Go's chain building with `x509.UnknownAuthorityError`, before VerifyConnection runs. The client therefore never sees the new root, and the error cannot name its pin.
  - Map that error (found with errors.As through the url.Error and tls.CertificateVerificationError wrappers) and VerifyConnection's own pin-mismatch error to one sentinel, `serverclient.ErrTLSRootNotPinned`.
  - Its message: "the server's TLS certificate does not chain to a root you pinned with keyroster init. If its CA changed roots, run `keyroster init --server <URL>` without --tls-pin (add --tls-root-file <new root PEM> for a private CA) to print the roots it now presents, compare the pins out of band (docs/runbooks/server-install.md \"TLS root changed\"), then re-run init with --tls-pin and --force".
  - Other x509 errors (expired leaf, wrong hostname) keep their own messages.

**CLI.**
- cmd/keyroster/config.go defines `Config{Server string; TLSRootsPEM []string; TLSPins []string; TrustPins []string; TrustThreshold int; User string; AdminKey string}` as JSON at `os.UserConfigDir()/keyroster/config.json`, written 0600 in a 0700 directory, with `loadConfig()` and `saveConfig(c, force bool)`.

- cmd/keyroster/init.go `keyroster init`:
  1. Validate --server: https, host a DNS name (net.ParseIP nil after stripping brackets), optional port, no path, query or fragment.
  2. Build the pool from --tls-root-file (PEM, at least one CA cert) or from x509.SystemCertPool.
  3. `tls.Dial` with ServerName and that pool. Collect the root (last element) of every VerifiedChain and print each root's subject and PinOf.
  4. Require at least one --tls-pin and that every given pin was observed. Without --tls-pin, print the observed pins and exit 2 with "compare these with your invite and re-run with --tls-pin".
  5. Keep only the observed roots whose pins were given.
  6. Through serverclient with those roots, call Trust(--root-pin, --threshold). Print the bundle version, the root fingerprints, the user CA fingerprint and the custody.
  7. saveConfig. It refuses an existing file without --force.
