<objective>
The MVP moment: `keyroster login` puts a short-lived certificate into the user's ssh-agent after the user approves the exact request with their passkey, and the user can SSH into a manually configured host.
- **The CLI** makes an ephemeral key, shows its fingerprint, principals and TTL, and runs the D-12 browser-loopback flow with state and PKCE. It verifies the certificate against the root-pinned user CA and adds it with a lifetime: SSH_AUTH_SOCK on Linux and macOS, keyroster's own agent on Windows.
- **The server** shows the same fingerprint on an approval page, accepts the assertion, and calls the signer only when the CLI redeems the code (mint at redemption, RESEARCH Q2).

Purpose:
- AUTH-03 (on Linux, macOS and Windows; CI covers the CLI on all three, the homelab covers real browsers in 02-14);
- AUTH-04 (fingerprint on both sides);
- PLAT-05;
- success criteria 2 and 3 end to end against real sshd.

Output: the login API, the approval page, `keyroster login`, the per-OS agent and browser glue, e2e coverage, and a PR through the merge gate.
</objective>

**DB.** `0004_login.sql` creates `login_sessions(id TEXT PRIMARY KEY, user_name TEXT NOT NULL, request BLOB NOT NULL, code_challenge TEXT NOT NULL, state TEXT NOT NULL, redirect_port INTEGER NOT NULL CHECK (redirect_port BETWEEN 1024 AND 65535), status TEXT NOT NULL CHECK (status IN ('pending','approved','redeemed')), assertion BLOB, code_hash BLOB UNIQUE, code_expires_us INTEGER, created_us INTEGER NOT NULL, expires_us INTEGER NOT NULL)`. Add the accessors `CreateLogin`, `Login(id, now)`, `ApproveLogin(id, assertion, codeHash, codeExpires)` and `RedeemLogin(id, codeHash, now)`. RedeemLogin moves approved to redeemed atomically, so it succeeds once.

**Server** (internal/server/login.go; each route has a per-IP limit and the API routes also a per-user limit):
- `GET /api/v1/login/options?user=NAME` returns, for an active directory user with at least one credential, `{"server_time": <unix>, "user", "ca_max_ttl_seconds", "roles": [{"name","principals","max_ttl_seconds","extensions"}]}`. Otherwise it returns the uniform 404.
- `POST /api/v1/login/begin {"request","code_challenge","code_challenge_method","state","redirect_port"}`:
  - `request` is base64 std of `LoginIssueRequest.Marshal()` with no evidence; ParseLoginIssueRequest it, and refuse any evidence;
  - the subject must be an active user;
  - |server now − CreatedAt| ≤ 300 s;
  - `code_challenge_method` must be `S256`, `code_challenge` must be 43 base64url characters, `state` 43 base64url characters, and `redirect_port` 1024-65535;
  - id = 16 random bytes in hex; expires = CreatedAt + 300 s;
  - return `{"login_id","approval_url": <first policy origin>/login/<id>,"expires_at"}`.
- `GET /login/{id}` renders login_approve.html for a pending session:
  - the fingerprint `ssh.FingerprintSHA256` of the SubjectKey parsed from the stored request bytes, shown large, with "Approve only if your terminal shows exactly this fingerprint. If you did not just run keyroster login, close this page.";
  - the user, the requested roles (or "all your roles"), each principal, the TTL in human form and the expiry time;
  - the attributes `data-assertion="/api/v1/login/<id>/assertion"`, `data-expires="<unix>"` and `data-options="<JSON: challenge = base64url(Digest()), allowCredentials = the user's directory credential ids, rpId, userVerification "required", timeout 60000>"` (html/template attribute escaping);
  - an expired, approved or redeemed session renders the uniform error page.
- `POST /api/v1/login/{id}/assertion {"credential_id","authenticator_data","client_data_json","signature"}`:
  1. the session must be pending and unexpired;
  2. pre-verify with `webauthn.VerifyAssertion` against the subject's directory credential, the policy RP and origins, with challenge = Digest() (a server-side early error only; the signer re-verifies);
  3. store `wire.WebAuthnAssertion{...}.Marshal()`, a 32-byte random code (store SHA-256), code_expires = now + 120 s, status approved;
  4. return `{"redirect": "http://127.0.0.1:" + stored port + "/callback?code=" + code + "&state=" + stored state}`.
- `POST /api/v1/login/{id}/redeem {"code","code_verifier"}`:
  1. RedeemLogin with SHA-256(code), checked against the code expiry;
  2. require `base64url(SHA-256(code_verifier)) == code_challenge` in constant time;
  3. build the stored request with Evidence = [{EvidenceWebAuthnAssertion, stored assertion}];
  4. call `signerclient.Login`;
  5. return `{"certificate": base64 std of the certificate's wire bytes}`.

  A signer refusal returns 403 `{"error": <detail>}`. Any other failure returns the uniform 400 `{"error":"login not redeemable"}`.

**Page JS** (app.js, `#kr-approve`):
- a countdown from data-expires;
- the Approve button parses data-options, decodes the challenge and credential IDs, calls `navigator.credentials.get({publicKey})`, posts base64url fields to data-assertion, and then runs `window.location.assign(resp.redirect)`;
- never `fetch` the loopback, never use a form for it, and never construct the loopback URL in JS.

**CLI** cmd/keyroster/login.go, `keyroster login [--role R]... [--ttl DURATION] [--no-browser]`:
1. loadConfig (requires `user`); serverclient.New; `Trust(...)` gives the bundle, from which the active user CA key comes.
2. GET options. When |local now − server_time| > 60 s, refuse "your clock differs from the server by Ns; fix it before logging in". Selected roles are --role (each must be among the options) or all of them. Principals are the sorted union, cap = min(role TTLs, ca_max_ttl), and extensions the union. `--ttl` larger than the cap is refused; the default TTL is the cap.
3. Make an `ed25519.GenerateKey` key with crypto/rand, in memory only. Build the request with RequestID 16 random bytes and CreatedAt now.
4. Print to stderr: `Login for <user>: principals <list>, valid <ttl>`, `Key fingerprint: SHA256:…` and "Approve in your browser only if it shows this fingerprint."
5. code_verifier = 32 random bytes in base64url, code_challenge = base64url(SHA-256(verifier)), state = 32 random bytes in base64url.
6. loopback.go: `net.Listen("tcp", "127.0.0.1:0")`. Its handler accepts only `GET /callback` with r.Host equal to `127.0.0.1:<port>` exactly (else 400), and state equal through subtle.ConstantTimeCompare (else 400, keep waiting). It answers a small HTML page "keyroster: approved, you can close this tab" with Cache-Control no-store, delivers the code once, then shuts down.
7. POST begin and print the approval URL. Unless --no-browser, call `openBrowser(url)`: xdg-open on Linux, `open` on macOS, `rundll32 url.dll,FileProtocolHandler` on Windows, nothing elsewhere. A failure to open is only a warning.
8. Wait for the callback until min(expires_at, CreatedAt + 270 s); on timeout fail with "login not approved in time".
9. POST redeem, then parse the certificate and verify:
   - a user certificate whose `SignatureKey` equals the user CA;
   - `Key` equal to the ephemeral public key;
   - ValidPrincipals equal to the requested set exactly;
   - KeyId parses (cert.ParseKeyID) as kr2 with Subject = user and Request = hex(RequestID);
   - ValidBefore − ValidAfter ≤ TTL + 300 (cert.Build's five-minute backdate);
   - ValidBefore − now ≥ 60.
10. Add to the agent (loginagent_*.go) `agent.AddedKey{PrivateKey, Certificate, LifetimeSecs: ValidBefore − now, Comment: KeyId}`:
    - Unix: dialAgent over SSH_AUTH_SOCK. When it is unset, fail with "start ssh-agent (eval $(ssh-agent)) and retry; keyroster never writes the key to a file". Apply the A3 decision from 02-02.
    - Windows: `winagent.Ensure(ctx, os.Executable())`.
    - On an Add error, return it wrapped with "the agent refused the key with a lifetime constraint; not retrying without it". Then List(); the certificate blob must be present, else fail "the agent dropped the certificate".
11. Print the principals, the expiry time in local time and, on Windows, `Use: ssh -o IdentityAgent=<pipe> ...` or the ~/.ssh/config line.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| CLI ↔ server (pinned TLS) | The server is untrusted for authority; the CLI verifies what comes back |
| browser page ↔ user | The user decides by comparing fingerprints |
| browser → loopback | The code travels only by top-level navigation to 127.0.0.1 |
| server → signer | Only at redemption; the signer re-verifies everything |
