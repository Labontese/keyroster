<objective>
Close the enrollment loop. `keyroster user approve` binds a registered passkey through an **admin-signed directory version**, the only thing the signer treats as authority. Every directory edit uses one pipeline with the same safeguards:
- the trust bundle is verified against the root pins;
- the installed directory is verified locally against the policy admins;
- the successor is built, validated and diffed;
- it is signed with the admin's SSH key;
- it is installed through the server, or saved as a proposal for co-signing when the quorum needs more admins.

The first admin enrolls the same way (D-04).

Purpose:
- AUTH-01 and success criterion 1: an account is unusable until the user registers a passkey and an admin binds it.
- KEY-02: authority is a quorum-signed directory version.
- D-01 to D-04.

The role and group commands of 02-10 reuse the pipeline.

Output: the pipeline, user approve/list/disable/enable, directory show/sign/install, server forwarding and mirror, an enrollment runbook, and a PR through the merge gate.
</objective>

**Server.**
- internal/server/directory.go keeps a directory mirror: it calls signerclient.GetDirectory when the cached Status's directory SHA-256 changes, and caches by version.
- `GET /api/v1/admin/directory` (requireAdmin) returns `{"version","directory","sigs","authorized"}` (base64 std).
- `POST /api/v1/admin/directory` (requireAdmin, body `{"directory","sigs"}`, 2 MiB limit) calls signerclient.InstallDirectory.
  - On success it refreshes the mirror. In one serverdb transaction (`DeleteBound`) it deletes each pending credential whose ID now appears in the directory, and each pending user now present in the directory with no remaining pending credential. It returns `{"version","sha256","leaf_index"}`.
  - On a signer refusal it returns 409 for `directory_version_chain`, 403 for the other unauthorized details and 400 for `directory_invalid`, with `{"error": <signer detail>}`.
- `GET /api/v1/admin/users` (requireAdmin) returns `{"directory_version", "users":[{"name","status","credentials":[{"fingerprint","alg","synced"}]}], "pending":[{"name","invite_expires_at","invite_used","credentials":N}]}`.

**internal/directory/diff.go.** `Diff(old, new *Directory) []string` returns stable, sorted lines such as `+ user alice (active)`, `+ credential alice SHA256:… ES256 synced=false`, `~ user bob active -> disabled`, and `+/- role …`, `+/- group …`, `+/- host_group …` with their members and principals. A nil old means genesis.

**cmd/keyroster/dirpipe.go.** `editDirectory(ctx, env cliEnv, opts editOpts, mutate func(d *directory.Directory, pol *trust.Policy) error) error`. opts holds `Yes bool`, `Out string` and `AdminKey string`. The steps:
1. loadConfig; serverclient.New; `Trust(cfg.TrustPins, cfg.TrustThreshold)` returns the bundle and policy.
2. GET /api/v1/admin/directory. When version > 0: `directory.Parse(doc)` and `directory.VerifySignatures(doc, sigs, policy)`, which must meet the quorum. On failure refuse with "the server's directory is not signed by the policy admins; refusing to build on it". When version is 0, the base is nil.
3. next = a deep copy of the base (or a new Directory with Version 1, Prev GenesisPrev and empty lists) with Version + 1 and Prev = trust.SHA256Hex(base bytes). Call mutate, then Sort, Validate and CheckPolicy.
4. Print Diff and the next version's SHA-256. Prompt `Sign directory version N? [y/N]` on the TTY unless --yes. With no TTY and no --yes, refuse.
5. Sign `next.Canonical()` with sshsig under directory.Namespace using the admin key from --admin-key or config.AdminKey, through agentSigner over dialAgent.
6. If `policy.AdminQuorum > 1` or --out is set: write `<Out>/directory.json` and `<Out>/directory.json.sigs` (armored SSHSIG blocks, newline-separated, the root sign convention) plus `<Out>/base.sha256`. Print the number of signatures present and needed and the next commands (`keyroster directory sign <Out>`, `keyroster directory install <Out>`). Otherwise POST /api/v1/admin/directory.
7. A 409 `directory_version_chain` becomes the error "the directory changed since it was read (another admin installed a version); re-run this command".

**cmd/keyroster/directory.go.**
- `keyroster directory show` prints the verified installed directory: version, SHA-256, signers, users with credential fingerprints, roles, groups and host groups.
- `keyroster directory sign DIR`:
  1. load the proposal;
  2. verify that it parses, that its prev equals the SHA-256 of the currently installed verified directory (or that it is genesis when none is installed), and that every existing signature is by a policy admin;
  3. print Diff against the installed base and confirm;
  4. append this admin's signature.
- `keyroster directory install DIR` posts the proposal.

**cmd/keyroster/user.go.**
- `user approve NAME --fingerprint FP [--yes] [--out DIR] [--admin-key]`: GET /api/v1/admin/users/NAME/pending. Without --fingerprint, print the pending fingerprints and exit 2 with "compare with the fingerprint the user saw and re-run with --fingerprint". Otherwise select the pending credential whose fingerprint equals FP; with none, refuse "no pending credential with fingerprint FP". The mutation adds User{NAME, active, [cred]} or appends the credential to an existing user. The credential is {id, alg, spki base64, backup_eligible, backed_up}.
- `user list`: GET /api/v1/admin/users, printed as a table.
- `user disable NAME` / `user enable NAME`: pipeline mutations that change Status.

| Boundary | Description |
|----------|-------------|
| server → admin CLI (base directory, pending credentials) | The server may lie; the CLI verifies the base against root-pinned policy admins and requires the out-of-band fingerprint |
| admin's agent key → directory signature | The admin's signature is authority; it must cover only what the admin saw |
| proposal files between admins | Files may be tampered with in transit |
