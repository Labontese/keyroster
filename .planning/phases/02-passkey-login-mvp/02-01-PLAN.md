<objective>
Phase tracer: prove the whole security core of Phase 2 end to end, without a web server or browser. The path:
1. a root-signed policy carrying the WebAuthn RP;
2. an admin-signed **directory** that binds a soft-authenticator credential to user `alice` and grants role `ops` the principal `role:ops`, installed online into the running signer;

It answers the riskiest architectural question first: can a network-less signer, using stdlib crypto only, authorize a passkey login that stock OpenSSH accepts?

- rp_id is 1-253 bytes of lowercase labels matching `^[a-z0-9]([a-z0-9-]{0,61}[a-z0-9])?$`, at least two labels and no trailing dot;

**internal/directory (new; imports only stdlib, internal/trust, internal/cert, internal/webauthn and golang.org/x/crypto/ssh).**
- Types: `const Namespace = "keyroster/directory/v1"`. The document types are `Directory{Version uint64; Prev string; Users []User; Groups []Group; Roles []Role; HostGroups []HostGroup}`, `User{Name, Status string; Credentials []Credential}`, `Credential{ID string; Alg int64; SPKI string; BackupEligible, BackedUp bool}`, `Group{Name string; Members []string}`, `Role{Name string; Principals []string; MaxTTLSeconds uint64; Extensions []string; Users []string; Groups []string}`, `HostGroup{Name string; Accounts []AccountMap}` and `AccountMap{Account string; Roles []string}`, with the json names of RESEARCH Pattern 1 (`backup_eligible`, `backed_up`, `max_ttl_seconds`, `host_groups`).

  - version ≥ 1, prev is 64 lowercase hex, and version 1 has prev = trust.GenesisPrev;
  - user, group and host-group names match `^[a-z0-9][a-z0-9._-]{0,63}$`, and role names match `^[a-z0-9][a-z0-9._-]{0,31}$` (this bounds key ID length);

  - credential `id` is base64url without padding decoding to 1-1023 bytes, `alg` is -7, -8 or -257, and `spki` is base64 std that `webauthn.ParsePublicKey(alg, spki)` accepts;
  - each role has 1-32 principals passing `cert.ValidatePrincipals` and `max_ttl_seconds` ≥ 60;
  - every list is non-null, sorted (credentials by id, the rest lexicographically) and duplicate-free;
  - credential ids are unique across the whole document, and every referenced user, group and role exists;
  - every active user has at least one credential (AUTH-01);
  - each user's effective roles (direct and via groups) number at most 16, and their principal union is within `cert.MaxPrincipals`.

**internal/webauthn (new; stdlib only, D-17).**
- Constants and types: `AlgES256 int64 = -7`, `AlgEdDSA = -8`, `AlgRS256 = -257`; `Credential{ID []byte; Alg int64; SPKI []byte}`; `Assertion{CredentialID, AuthenticatorData, ClientDataJSON, Signature []byte}`.
- `ParsePublicKey(alg int64, spki []byte) (crypto.PublicKey, error)` uses x509.ParsePKIXPublicKey plus an alg-matching type switch: P-256 only for ES256, ed25519.PublicKey for EdDSA, RSA with N.BitLen() ≥ 2048 for RS256. `Fingerprint(spki []byte) string` returns `SHA256:` plus unpadded std base64 of SHA-256(spki).
- `VerifyAssertion(cred Credential, rpID string, origins []string, challenge [32]byte, a Assertion) error` runs in this order, returning the named sentinel at each step:
  1. the assertion's credential ID equals cred.ID: ErrCredentialID;
  2. authData is exactly 37 bytes: ErrAuthenticatorData;
  3. rpIdHash equals SHA-256(rpID), compared with crypto/subtle: ErrRPMismatch;
  4. UP is set (ErrUserPresence) and UV is set (ErrUserVerification); AT or ED set gives ErrAuthenticatorData;
  5. clientDataJSON parses: ErrClientData;
  6. type is `webauthn.get`: ErrType;
  7. challenge decodes as strict base64url without padding and equals the challenge in constant time: ErrChallenge;
  8. origin is exactly one of origins: ErrOrigin;
  9. crossOrigin is true or topOrigin is present: ErrCrossOrigin;
  10. the signature over authData ‖ SHA-256(clientDataJSON) verifies with ecdsa.VerifyASN1 for ES256, ed25519.Verify for EdDSA, or rsa.VerifyPKCS1v15 with SHA-256 for RS256 (ErrSignature); any other alg gives ErrAlgorithm.
- clientdata.go walks exactly one top-level JSON object with the encoding/json v1 `Decoder.Token()` API (json/v2 needs go 1.27; go.mod says 1.26). It refuses input over 2048 bytes, invalid UTF-8, duplicate member names, non-string `type`/`challenge`/`origin`/`topOrigin`, a non-bool `crossOrigin` and trailing data. It skips unknown members, because browsers inject extra keys.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| keyroster-admin group peer → signer | Any allowed peer (later the web server) may send login and directory messages; it may be compromised and must not be able to authorize anything itself |
| user authenticator → signer | The assertion is the only thing a compromised server cannot forge; it binds the exact request bytes |
| admin keys → directory | Credential and role bindings are authority only when signed by the policy's admin quorum |
