<objective>
Let an invited user register a passkey. The flow:
1. The invite page runs the WebAuthn create ceremony with one hand-written JS file.
2. go-webauthn, server only and reviewed by the owner first, verifies the attestation-none registration.
3. The server keeps the credential as a **pending** SPKI with its fingerprint, shown to the user.
4. The admin sees the same fingerprint with `keyroster user pending`.

The credential grants nothing until 02-09's admin-signed directory binds it.

Purpose:
- AUTH-01: every account must register at least one passkey.
- UI-01: the registration page.
- D-03 steps 2 and 3, and D-05: any authenticator, UV required, attestation none, BE/BS recorded.
- D-17: CBOR stays out of the signer.

Output: the registration endpoints and page, app.js, `keyroster user pending`, a differential oracle for the signer's verifier, dependency bans, and a PR through the merge gate.
</objective>

**Server.**
- enroll.go builds a go-webauthn instance per request from the cached status: RPID = rp_id, RPOrigins = policy origins, display name `keyroster`, attestation preference none, authenticator selection with userVerification required and residentKey preferred, credential parameters restricted to EdDSA, ES256 and RS256 (the L3 recommended set in v0.18.2).
- `POST /api/v1/enroll/{token}/begin` requires a valid, unused, unexpired invite. It runs BeginRegistration for a user with the pending user_handle and name, with excludeCredentials = the user's credentials in the installed directory. It stores the session data (5 min) and returns the creation options JSON.
- `POST /api/v1/enroll/{token}/finish`:
  1. load and delete the session (single use);
  2. parse the body with go-webauthn's creation-response parser and run CreateCredential/FinishRegistration, which requires UV;
  3. credential.go converts the COSE public key with webauthncose to an `x509.MarshalPKIXPublicKey` SPKI: EC2 to ecdsa P-256, OKP to ed25519, RSA from modulus and exponent. It then calls `webauthn.ParsePublicKey(alg, spki)` and refuses (400 `unsupported credential`) anything it rejects;
  4. refuse 409 if the credential ID is pending or in the installed directory;
  5. in one transaction, insert pending_credentials with BE/BS from the credential flags and set invite_used_us;
  6. return `{"fingerprint": webauthn.Fingerprint(spki), "algorithm": "<EdDSA|ES256|RS256>", "synced": <backed_up>}`.
- Rate limits use the invite limiter from 02-07.
- admin.go adds `GET /api/v1/admin/users/{name}/pending` (requireAdmin), returning `[{"id","alg","spki","fingerprint","backup_eligible","backed_up","registered_at"}]`.

**Page and JS.**
- enroll.html renders a `<main id="kr-enroll" data-begin="/api/v1/enroll/<token>/begin" data-finish="/api/v1/enroll/<token>/finish">` (html/template attribute escaping) with a "Register passkey" button, a result area and an error `<p role="alert">`, and `<script src="/static/app.js" defer></script>`. - static/app.js (plain ES2017, no modules from outside, about 150 lines) has base64url helpers. On click it:

- clientDataJSON has type webauthn.create, the options' challenge and the origin.
