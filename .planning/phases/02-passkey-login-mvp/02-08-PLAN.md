<objective>
Let an invited user register a passkey. The flow:
1. The invite page runs the WebAuthn create ceremony with one hand-written JS file.
2. go-webauthn, server only and reviewed by the owner first, verifies the attestation-none registration.
3. The server keeps the credential as a **pending** SPKI with its fingerprint, shown to the user.
4. The admin sees the same fingerprint with `keyroster user pending`.

The credential grants nothing until 02-09's admin-signed directory binds it.

Purpose:
- AUTH-01: every account must register at least one passkey.
- UI-01: the registration page.
- D-03 steps 2 and 3, and D-05: any authenticator, UV required, attestation none, BE/BS recorded.
- D-17: CBOR stays out of the signer.

Output: the registration endpoints and page, app.js, `keyroster user pending`, a differential oracle for the signer's verifier, dependency bans, and a PR through the merge gate.
</objective>

**DB.** `migrations/0002_registration.sql` adds:
- `registration_sessions(invite_hash BLOB NOT NULL, challenge TEXT NOT NULL, session BLOB NOT NULL, expires_us INTEGER NOT NULL, PRIMARY KEY (invite_hash, challenge))`. Each begin gets its own row, so concurrent ceremonies never overwrite each other's session (addresses review finding 02-08-F1);
- `pending_credentials(id TEXT PRIMARY KEY, user_name TEXT NOT NULL REFERENCES pending_users(name), alg INTEGER NOT NULL, spki BLOB NOT NULL, backup_eligible INTEGER NOT NULL CHECK (backup_eligible IN (0,1)), backed_up INTEGER NOT NULL CHECK (backed_up IN (0,1)), registered_us INTEGER NOT NULL)`. The CHECKs follow the signerdb migration style (addresses review finding 02-08-F11);
- `CREATE UNIQUE INDEX pending_credentials_one_per_user ON pending_credentials(user_name)`: at most one pending credential per user (02-08-F1);
- `ALTER TABLE pending_users ADD COLUMN invite_used_us INTEGER`.

Add the accessors to db.go:
- `CreateRegistrationSession(inviteHash []byte, challenge string, session []byte, expiresUS, nowUS int64) error`. It first deletes every expired session row. It then refuses with `ErrTooManySessions` when the invite already has 16 unexpired sessions, and otherwise inserts.
- `ConsumeRegistrationSession(inviteHash []byte, challenge string, nowUS int64) ([]byte, error)` runs `DELETE FROM registration_sessions WHERE invite_hash = ? AND challenge = ? RETURNING session, expires_us`. No row gives `ErrNotFound`, and an expired row (already deleted by the statement) gives `ErrExpired`. A session can therefore be consumed exactly once, atomically.
- `BindPendingCredential(inviteHash []byte, nowUS int64, cred PendingCredential) error` runs one transaction:
  1. `UPDATE pending_users SET invite_used_us = ? WHERE invite_hash = ? AND invite_used_us IS NULL AND invite_expires_us > ? RETURNING name`. Unless exactly one row comes back, it rolls back and returns `ErrInviteNotValid`; the invite was used, expired or replaced by a reinvite;
  2. inserts pending_credentials for that name. A primary-key or one-per-user constraint failure rolls back and returns `ErrDuplicateCredential`.
- Extend 02-07's `ReplaceInvite` (reinvite semantics; addresses review findings 02-08-F7 and 02-07-F5). In the same transaction as the invite_hash and expiry swap, it sets `invite_used_us = NULL`, deletes the registration_sessions rows of the old invite_hash, and deletes the user's pending_credentials. An unapproved credential from a replaced invite is discarded, and the user registers again under the new invite. The pending row keeps its user_handle, so re-registering on the same authenticator replaces the orphaned passkey there.

**Server.**
- enroll.go builds a go-webauthn instance per request from the cached status: RPID = rp_id, RPOrigins = policy origins, display name `keyroster`, attestation preference none, authenticator selection with userVerification required and residentKey preferred, credential parameters restricted to EdDSA, ES256 and RS256 (the L3 recommended set in v0.18.2).
- `POST /api/v1/enroll/{token}/begin` requires a valid, unused, unexpired invite. It runs BeginRegistration for a user with the pending user_handle and name, with excludeCredentials = the user's credentials in the installed directory. It stores the session data (5 min) with CreateRegistrationSession under the session's challenge, the base64url string go-webauthn keeps in its session data (confirm the field name in the module cache). It returns the creation options JSON. Too many open sessions gives 429.
- `POST /api/v1/enroll/{token}/finish` (the order makes consumption atomic; addresses review finding 02-08-F1):
  1. parse the body with go-webauthn's creation-response parser, and take the challenge string from its parsed clientDataJSON. That value is untrusted and used only as a lookup key; go-webauthn compares it with the session challenge in step 3;
  2. ConsumeRegistrationSession(hash(token), challenge): single use, atomic. No row or an expired one is refused, with nothing written;
  3. run CreateCredential/FinishRegistration with that session, which requires UV;
  4. credential.go converts the COSE public key with webauthncose to an `x509.MarshalPKIXPublicKey` SPKI: EC2 to ecdsa P-256, OKP to ed25519, RSA from modulus and exponent. It then calls `webauthn.ParsePublicKey(alg, spki)` and refuses (400 `unsupported credential`) anything it rejects;
  5. the canonical credential ID is `base64.RawURLEncoding` of the credential ID bytes that FinishRegistration returns, never the client's `id` or `rawId` string. Refuse 409 if that string is a pending credential's id or a credential id in the installed directory (addresses review finding 02-08-F10);
  6. BindPendingCredential(hash(token), now, {canonical id, alg, spki, BE/BS from the credential flags}). ErrInviteNotValid gives the uniform 404 "invite not valid" with nothing inserted, and ErrDuplicateCredential gives 409. Because the UPDATE matches on the URL's invite hash, a ceremony begun under a token that a reinvite has since replaced cannot land a credential;
  7. return `{"fingerprint": webauthn.Fingerprint(spki), "algorithm": "<EdDSA|ES256|RS256>", "synced": <backed_up>}`.
