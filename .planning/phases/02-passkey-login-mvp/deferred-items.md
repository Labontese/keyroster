| 02-07 (pre-merge review, for 02-09) | `requireAdminLimit` now verifies the signature before its handler reads any body (owner decision D2). 02-09-PLAN.md assumes the old order in several places. L51, L182, L469 and L497 say the install route's limit applies "while the body is read, before any signature work". L183 and L497 say the server "reads a larger body before authentication", bounded by T-02-36. L320 says "the same oversized body with no admin headers also answers 413". What holds now: (1) a declared Content-Length over the limit gets 413 before any signature work, with the nonce unused, so L320 and `over_route_limit_413_no_signer_call` hold as written for a body sent with its length; (2) a body without a Content-Length is read only after Verify, so an oversized one gets 413 after Verify with the nonce unused, and one without valid admin headers gets the uniform 401 without the handler reading it; (3) the handler never reads or buffers an unauthenticated body, so the "larger read before authentication" no longer exists in the handler. net/http still reads some of such a body. Over HTTP/1.1 it may discard up to 256 KiB of it after the refusal, and a stalled body holds the connection until ReadTimeout (30 s in serve.go). Over HTTP/2, which keyroster-server negotiates by default, it buffers the stream's DATA in memory whether or not the handler reads, up to the receive windows (by default 1 MiB per stream and 1 MiB per connection), until the handler returns, and then resets the stream; there is no 256 KiB drain. That exposure is in the Phase 6 todo `2026-10-20-cap-server-connections-and-memory.md`. `maxDirectoryInstallBody` now bounds the read of a verified admin's request only, and needs no T-02-36 cover. | 02-09's design and wording, not 02-07's code. 02-09 should restate L51, L182, L183, L469 and L497 in these terms and keep its three body-limit tests. |
| 02-07 (pre-merge review, for 02-08 and 02-09) | The admin message changed once (D1 and D2), with the namespace `keyroster/admin-api/v1` kept because 02-07 is unreleased. It now covers the namespace, the canonical origin of the server URL (`https://host[:port]`, lowercase, no trailing dot, no `:443`), the method, the raw request-target, the body's SHA-256, the time and the nonce. The digest also travels in `Keyroster-Admin-Body-SHA256`, exactly 64 lowercase hex digits. `adminauth.Sign` takes the origin. `adminauth.Verify` takes the origin, reads no body and returns the signed digest, and `adminauth.CheckBody` checks the body after it is read. The server verifies only against a policy origin it matched exactly from the Host header, so an admin's `--server` must be a policy origin. Effects on later plans: (a) tests that build admin requests must use the test helpers `signedReq`/`signedReqFor` or `adminauth.Sign` with an origin. (b) The body-less GETs (02-08 L236 `GET /api/v1/admin/users/{name}/pending`, 02-09 L193 and L210) sign the SHA-256 of the empty body. `serverclient.AdminJSON` marshals its input as the request body, so a nil input sends and signs `null`; 02-08/02-09 should send GETs without a body. (c) `requestOrigin`'s fallback to the first sorted origin can no longer be reached on an admin route, because authentication already requires the exact origin. 02-12's approval URL reuses `requestOrigin` on a login route, where the fallback still applies. | Interface change made by the 02-07 pre-merge fixes; the later plans' text predates it. |
