| 02-01 | In WSL, `bash scripts/linux.sh 'go test ... && test -z "$(gofmt -l .)" && ...'` passes the gofmt step without checking anything. `gofmt` is not on the PATH of the WSL login shell (`gofmt: command not found`), and the command substitution expands in the outer Git Bash shell, so the test sees empty output. The plan's full gate therefore does not check formatting when run that way. CI's lint job runs gofmt properly. 02-01 checked formatting with the Windows toolchain's `gofmt -l .` and with `$(go env GOROOT)/bin/gofmt -l .` from a script file in WSL: both clean. | Environment quirk in the local gate command, not in 02-01's code. A fix (put `$(go env GOROOT)/bin` on the WSL PATH, or call the gate from a script file) belongs to whichever plan next edits the gate or `scripts/linux.sh`. |
| 02-03 (pre-merge review, for 02-12) | 02-12-PLAN.md (line 48) says "a server showing a false fingerprint gets a signer refusal". That holds against page tampering but not against a compromised server: the authenticator never signs the fingerprint the page displays, only the challenge. A compromised server can show the CLI key's fingerprint while the challenge covers a request with its own key, and the signer then issues for the server's key. The CLI's own-key check (02-12) means the user gets no certificate that time, but the server then holds a valid certificate for the user's principals. 02-12 must correct that claim or design around it. | It concerns 02-12's design and wording, not 02-03's code. Recorded here so 02-12 planning sees it. |
| 02-03 (pre-merge review, second round) | `internal/signer/log_test.go#TestCheckLogAgainstLiveSigner` flakes under `-race` in WSL: about 1 in 40 runs fails with `unavailable: clock_regression` from one of its 60 back-to-back issuances. It fails at `ae57f1a` (before the review fixes) at the same rate, so it is not caused by them. Likely cause, not confirmed: the serial high-water mark runs ahead of the microsecond wall clock when issuances come faster than the clock advances. | Pre-existing and outside the review findings. Needs a look at how a serial is chosen when the clock has not advanced since the last one; belongs to the next plan that edits issuance or that test. |
