Create branch `p02/10-web-signin` from `origin/main`.

**DB.** `0003_web.sql` adds `web_challenges(id TEXT PRIMARY KEY, user_name TEXT NOT NULL, challenge BLOB NOT NULL, expires_us INTEGER NOT NULL)` and `sessions(id_hash BLOB PRIMARY KEY, user_name TEXT NOT NULL, created_us INTEGER NOT NULL, last_seen_us INTEGER NOT NULL)`. db.go gains `CreateChallenge`, `TakeChallenge(id, now)` (delete-returning; expired or absent gives ErrNotFound), `CreateSession`, `TouchSession(hash, now, idle, absolute)` and `DeleteSession`.

**weblogin.go.**
- `GET /login` renders login.html: `<main id="kr-login" data-begin="/api/v1/web/login/begin" data-finish="/api/v1/web/login/finish">` with a username input, a submit button and a `<p role="alert">`.
- `POST /api/v1/web/login/begin {"user"}`. The user must be active in the directory mirror with at least one credential. Otherwise answer 404 `{"error":"no usable passkey for this user"}`, identical for unknown, pending, disabled and credential-less users. Create a 32-byte challenge with a 120 s expiry and return `{"challenge_id", "publicKey": {"challenge", "allowCredentials":[{"type":"public-key","id"}], "rpId", "userVerification":"required", "timeout":60000}}` (base64url).
- `POST /api/v1/web/login/finish {"challenge_id","credential_id","authenticator_data","client_data_json","signature"}`:
  1. TakeChallenge;
  2. re-check that the user is active and that the credential belongs to them in the current mirror;
  3. `webauthn.VerifyAssertion(cred, rp_id, origins, challenge, assertion)`;
  4. create a session ID (crypto/rand, 32 bytes, base64url) and store its SHA-256;
  5. Set-Cookie `__Host-keyroster-session=<id>; Path=/; Secure; HttpOnly; SameSite=Strict; Max-Age=43200`;
  6. return `{"redirect":"/account"}`.

  Any failure returns 401 `{"error":"sign-in failed"}` and logs the specific reason through slog.

**session.go.**
- `withSession(next)` reads the cookie, hashes it and calls TouchSession with idle 1 h and absolute 12 h. It requires the user to still be active in the mirror, otherwise it deletes the session. It puts the user name into the request context. A missing or invalid session redirects HTML routes with 303 to /login.
- `POST /logout` deletes the row, sets the same cookie with Max-Age=0, and redirects 303 to /login. CrossOriginProtection from 02-06 already wraps it.

**account.go.** `GET /account` (withSession) renders account.html with:
- name, status, directory version;
- `Authorize(user, nil)`: each role with its principals and max TTL, the overall TTL cap min(role caps, user CA cap), or "no roles yet" when the user has none;
- each credential's `webauthn.Fingerprint`, its algorithm, and "synced" when backed_up, else "device-bound";
- a logout form;
- the text "Read only. Ask an admin to change roles or credentials."

**Rate limits.** ratelimit.go adds a per-username limiter next to the per-IP one: begin and finish allow 20/min with burst 10 per IP, and 10/min per username.

**app.js** gains the sign-in ceremony on `#kr-login`: begin, decode, `navigator.credentials.get({publicKey})`, then post `{challenge_id, credential_id: rawId, authenticator_data, client_data_json, signature}` (base64url) to finish, then `location.assign(redirect)`. index.html links to /login and /account.

**e2e** test/e2e/websignin_test.go `TestWebSignInEndToEnd`:

4. The policy origin is `https://keyroster.localhost:<port>`, set by the 02-06 helper `startServerEnv`, because a test server is never on port 443.
