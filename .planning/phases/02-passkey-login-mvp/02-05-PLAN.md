The backend keeps no passphrase between calls; Provision and each Key call read it from its source again. **Status (D-18).**
- wire/status.go defines `TypeStatus byte = 0x04` (empty body) and `TypeStatusResponse byte = 0x84`, and `StatusResponse{Keys []KeyStatus; BundleVersion uint64; Bundle, BundleSigs, Policy, PolicySigs []byte; DirectoryVersion uint64; DirectorySHA256 [32]byte; DirectoryAuthorized bool}` with `KeyStatus{Role, Alg, Custody, Fingerprint string}`.
  - Encoding: u8 count (5 roles), u16 strings, u24 documents, strict decode.
  - `MaxStatusFrame = 256 << 10` is a frame-length cap under 02-03's single unit rule: the frame length counts the 2 header bytes (version, type) plus the body. In frame.go, `maxBodyFor(TypeStatusResponse)` therefore returns `MaxStatusFrame − headerLen`, and ReadMessage and WriteMessage apply it as they do every other per-type cap.
  - `(*StatusResponse).Marshal() ([]byte, error)` returns `wire.ErrStatusTooLarge` when the encoded body would exceed `MaxStatusFrame − headerLen`, the same limit in the same unit as maxBodyFor. The error names the body size and that limit. Marshal never truncates.
- One budget for install and Status (addresses review finding 02-05-F6). Phase 1's install-bundle reads its four files without a size cap, and only the bundle_install leaf limits each to tlog.MaxDocument (1 MiB). That is far above what Status can carry, so an accepted install could make Status, and with it every issuance and the server, fail.
  - Add an unexported `statusResponse(caKeys []signerdb.CAKey, bundleVersion uint64, bundle, bundleSigs, policy, policySigs []byte, dir statusDirectory) *wire.StatusResponse` in internal/signer/status.go, where `statusDirectory` is a small local struct holding the directory version, SHA-256 and authorized flag (all fixed-size on the wire). Both Signer.Status and InstallBundle use it.
  - In InstallBundle (internal/signer/trust.go), right after `db.CAKeys` and before any verification or `lw.logTx`, build the would-be reply from the ca-init keys and the four incoming documents, with fixed-size directory fields, and call Marshal. On ErrStatusTooLarge, refuse with `ErrBundleInstall` wrapping it: "the bundle, policy and signatures make a Status reply body of N bytes, above the M-byte limit (wire.MaxStatusFrame minus the 2-byte header)". Nothing is stored and no leaf is written.
  - Install and Status then share one encoder and one limit, so they cannot disagree. A trust state installed by Phase 1 code above the budget (not expected: real bundles and policies are a few KiB) makes Status return the same explicit error. The server then serves 503 and `ca issue` aborts; nothing fails silently.
- `Signer.Status()` runs under s.mu. It builds the response with statusResponse from the keys and custody re-checked at start, the trust_bundle row in force, and the directory state; it adds no new state.
  - Custody and keys are fixed for the life of the signer process: openRoleKey opens them only at start. A bundle installed under a running signer makes it refuse every request with `trust_changed` until a restart (issue.go checkTrustCurrent). A Status reply and the issuance that follows it therefore cannot disagree about custody without a restart between them, so IssueResponse carries no extra version field (addresses review finding 02-05-F11).
- Dispatch it in server.go and add `signerclient.Status(ctx, socket)`.
