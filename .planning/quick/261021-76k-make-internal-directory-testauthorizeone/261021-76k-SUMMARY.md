# Quick 261021-76k: TestAuthorizeOneUser as the fastest of five interleaved runs. Summary

TestAuthorizeOneUser now times 5 interleaved rounds of `Validate` and `Authorize`. It fails when the fastest Authorize exceeds the fastest Validate divided by 20, the same bound as before.
- A single stalled sample no longer fails the test, which is the cli-windows false FAIL.
- A single stalled sample also no longer passes the test, which was a false PASS that hid R1.
- R1 (Authorize computing every user's roles) still fails 10 of 10 runs.

## Why

**The CI failure.** cli-windows failed with `Authorize of one user took 9.4551ms, Validate of 20000 users 99.4036ms` (run **39432354498**, job **118660357874**).
- Normally Authorize takes about 1 ms against about 62-75 ms for Validate.
- The old test judged one wall-clock sample of each, so one scheduler or GC stall decided the result.

**What the test guards.** R1 is the regression from plan 02-03: `f35f03e` made Authorize call `userRoles` instead of `roleGrants`. The signer runs Authorize under its lock for every login (T-02-12). The test must keep failing an Authorize that computes every user's roles.

## Shape of the new test (commit d6bb961)

- **Rounds.** `const rounds = 5`. Each round times `d.Validate()` and then `authz.Authorize(last.Name, nil)`. The correctness checks are kept as before: Validate returns nil, and Authorize gives all `MaxRolesPerUser` roles.
- **A copy for Authorize.** Authorize runs on a shallow copy: `authz := *d`, with `authz.Users = slices.Clone(d.Users)`, and only the copy's last user is set active.
  - Validate keeps running on `d`, where every user is disabled, because Validate refuses an active user that has no credential.
  - `Directory` has no mutex, so the copy passes `go vet` (copylocks).
- **The comparison.** The test fails when `slices.Min(authorizes) > slices.Min(validates)/20`. The Fatalf and the Logf both print the fastest value and every sample of each call.
- **No new imports, no production change.** `slices` and `time` were already imported, and only `directory_test.go` differs from origin/main under `internal/directory`.
- **Why Validate is also measured 5 times.** One stalled Validate sample loosens the bound enough to let R1 pass. The old test shows this (1b below), and the new test does not (2c below).
